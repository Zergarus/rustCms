# Корзина и торговый каталог — дизайн

Дата: 2026-10-07. Подпроект 1 из 4 этапа «Коммерция» (корзина → оформление заказа →
заказы в профиле → онлайн-оплата).

## Цель и критерии успеха

Цель этапа «Коммерция» — рабочая демонстрация магазина на CMS: на неизменённом фронте,
написанном под модуль `mediagroup.bxapi`, посетитель (гость или вошедший) кладёт товар в
корзину и выбирает склад, оформляет заказ, оплачивает через тестовый магазин ЮKassa и
видит заказ в профиле. Перенос исторических заказов и брошенных корзин, скидки, QR
Альфа-Банка, PDF-счета и чеки ОФД в этап не входят.

Корзина готова, когда:

- фронт работает с корзиной через контракт bxapi (раздел «5. Корзина» `FRONTEND_API.md`)
  без правок: добавление, количество, смена склада, удаление, очистка, снимок со `snapshot`;
- корзина гостя хранится на сервере и при входе объединяется с корзиной пользователя;
- количество ограничено остатками по правилам торгового каталога Битрикса;
- в админке есть раздел «Магазин»: склады, корзины покупателей, типы цен, валюты,
  настройки каталога, а любой инфоблок можно сделать торговым каталогом с вкладкой
  «Торговый каталог» у товаров.

Всё ниже — ядро CMS: у каждой части есть аналог в модулях `sale` и `catalog` Битрикса.
Настройки конкретного сайта задаются в его модуле проекта (`projects/<имя>.rs`).

## Модель данных

Новые таблицы (аналоги модуля `sale`):

- **`buyers`** (как `b_sale_fuser`) — владелец корзины: `id`, `user_id` (NULL у гостя,
  уникален, если задан), `token_hash` (sha256 токена из cookie гостя, уникален, если
  задан), `created_at`, `updated_at`.
- **`cart_items`** (как `b_sale_basket`) — позиция: `id`, `buyer_id` → `buyers`
  (каскадно), `element_id` → `iblock_elements` (каскадно), `store_id` → `catalog_stores`
  (NULL — склад не выбран; при удалении склада — NULL), `quantity` (NUMERIC > 0), `name`
  (название на момент добавления), `price`, `currency` (последняя рассчитанная цена),
  `order_id` (NULL, пока позиция в корзине; заполняется при оформлении заказа в следующем
  подпроекте), `created_at`, `updated_at`. Уникальность: один товар на одном складе — одна
  позиция в корзине (`buyer_id, element_id, store_id` при `order_id IS NULL`, склад NULL
  считается одним значением).

Расширения существующих таблиц (аналоги модуля `catalog`):

- **`catalog_products`** — флаги `available`, `quantity_trace`, `can_buy_zero`
  (из `b_catalog_product`; значение `D` раскрывается при переносе по настройкам каталога).
- **`catalog_stores.extra`** (JSONB) — UF-поля склада (`b_uts_cat_store`), ключи в
  snake_case: `uf_city_id` и любые другие.
- **`options`** (модуль `catalog`) — значения по умолчанию: `default_quantity_trace`,
  `default_can_buy_zero`.

Товар каталожного инфоблока без строки в `catalog_products` получает флаги по умолчанию
из настроек каталога и общий остаток 0; строка создаётся при первом сохранении вкладки
«Торговый каталог». Товар без цены недоступен для покупки.

Перенос (`import-bitrix`): флаги товаров, UF-поля складов, настройки каталога. Корзины из
`b_sale_basket` не переносятся.

## API (контракт bxapi)

| Метод | Путь | Тело |
|---|---|---|
| GET | `/api/v1/cart` | — |
| POST | `/api/v1/cart/items` | `{productId, quantity, storeId?}` |
| POST | `/api/v1/cart/items/{id}/quantity` | `{quantity}`; `0` удаляет позицию |
| POST | `/api/v1/cart/items/{id}/store` | `{storeId}` |
| POST | `/api/v1/cart/items/{id}/remove` | — |
| POST | `/api/v1/cart/clear` | — |

Каждый ответ — полный снимок корзины.

### Владелец корзины

- Вошедший пользователь — по сессии (`auth`); запись `buyers` создаётся при первой
  необходимости.
- Гость — по cookie `CMS_BUYER` (HttpOnly, SameSite=Lax, год). Cookie и запись `buyers`
  создаются только при первом добавлении товара; чтение пустой корзины их не создаёт.
- Объединение: в `auth/login` после успешного входа позиции гостя переносятся в корзину
  пользователя (одинаковый товар на одном складе — количества складываются), запись
  гостя удаляется, cookie `CMS_BUYER` стирается. Всё в одной транзакции.

### Снимок корзины

Позиция:

- `id`, `productId`, `name`, `quantity`;
- `price`, `currency` — пересчитываются при каждом чтении, как `catalogPrice`: базовый тип
  цены, иначе первый по сортировке; `sum` = `price × quantity`;
- `slug` — URL товара по шаблону `DETAIL_PAGE_URL` инфоблока;
- `article` — значение свойства артикула из настроек проекта;
- `image` — строка-путь по правилу картинки товара (`image_source` проекта, иначе анонс,
  иначе детальная);
- `stores[]` — активные склады, у которых есть запись остатка товара: `id`, `name`,
  поля карточки склада из настроек (по умолчанию `address`, `phone`), `amount`,
  `isAvailable` (`amount > 0`), `selected`, UF-поля склада по карте проекта
  (`uf_city_id` → `cityId`);
- `store` — выбранный склад в том же формате без `amount`/`isAvailable`/`selected`, или
  `null` (не выбран либо деактивирован);
- `isAvailable` — товар активен, `available`, у него есть цена, его инфоблок — торговый
  каталог;
- `properties` — свойства позиции из настроек проекта; пути через точку
  (`MARKS.ELEMENT.NAME`, `STATUS.ITEM.VALUE`) разбираются тем же механизмом, что `select`
  в каталоге; ключи camelCase;
- `snapshot` — sha1 от `id|productId|quantity|price|storeId`.

Итоги: `totalPrice` (сумма `sum`), `itemsCount` (штуки или позиции — настройка),
`canCheckout` (корзина не пуста, все позиции доступны, обязательные свойства заполнены,
например склад), `currency`, `empty`, `snapshot` — sha1 от снимков позиций в порядке `id`.

### Правила

- **Остатки.** Если у товара `quantity_trace` и не `can_buy_zero`, количество не может
  превышать остаток: на выбранном складе, а без склада — общий остаток. Нарушение — ошибка
  `cart_change_failed` («Доступно N шт.»), корзина не меняется.
- **Склад** можно выбрать только активный и только из `stores[]` позиции; иначе
  `cart_change_failed` («Склад N недоступен»). Если смена склада приводит к позиции,
  совпадающей с уже существующей (тот же товар на том же складе), они объединяются.
- **Ошибки:** `product_not_found` (нет товара, он неактивен или не в торговом каталоге, HTTP 404),
  `cart_item_not_found` (позиции нет или она чужая, HTTP 404), `cart_change_failed`
  (HTTP 400), `invalid_quantity` (не положительное число, HTTP 400).

### Настройки проекта (аналог `bxapi.basket`)

`article_property` (код свойства артикула), `item_properties` (пути свойств позиции и
необязательные алиасы), `store_fields` (поля карточки склада, по умолчанию адрес и
телефон), `store_user_fields` (UF склада → ключ ответа), `items_count_mode`
(`units` | `positions`), `required_props` (например, `store`), `image_width` (ширина
картинки позиции, без неё — оригинал).

## Админка

Раздел **«Магазин»** в боковом меню, право группы `shop.manage` (суперадмину доступен
всегда):

- **Склады** — список и форма: название, активность, сортировка, адрес, телефон, email,
  график, город (выбор местоположения → `uf_city_id`).
- **Корзины покупателей** — список непустых корзин (покупатель или «гость», число
  позиций, сумма, дата изменения) и просмотр позиций (товар, склад, количество, цена).
  Только просмотр.
- **Типы цен** — код, название, базовый, сортировка.
- **Валюты** — код и формат вывода: строка формата (`# &#8381;`), десятичный разделитель,
  разделитель тысяч, знаков после запятой, скрывать нулевые копейки.
- **Настройки каталога** — значения по умолчанию «учитывать количество» и «покупать при
  нулевом остатке».

В форме инфоблока — флаг **«Торговый каталог»** (`iblocks.is_catalog`). Пока он включён,
у товаров инфоблока в форме есть вкладка **«Торговый каталог»** (цены по типам цен,
остатки по складам, флаги `available`, `quantity_trace`, `can_buy_zero`), API отдаёт
`catalogPrice` / `stocks` / `catalogQuantity`, товары можно класть в корзину. При
выключении цены и остатки сохраняются, но не показываются; позиции инфоблока в корзинах
становятся недоступными.

Торговые предложения (SKU) в этап не входят.

## Устройство кода

- Расчёт снимка — чистая функция без БД: позиции, товары, цены, остатки, склады,
  настройки → снимок. Обработчики загружают данные пачкой (4–5 запросов на `GET /cart`
  независимо от числа позиций) и сохраняют изменения.
- Изменения корзины и объединение при входе — в транзакции; повторное добавление —
  через уникальный индекс и `ON CONFLICT`.
- Гонка «два запроса одновременно взяли последний остаток» в корзине не закрывается;
  остаток окончательно проверяется при оформлении заказа.

## Проверка

- Модульные тесты (TDD): стабильность и изменение `snapshot`; объединение корзин; лимиты
  остатков (склад, общий, `can_buy_zero`, без учёта количества); выбор цены и отсутствие
  цены; проверка склада; `canCheckout`.
- Сквозной сценарий через фронт: гость кладёт товар → выбирает склад → меняет количество →
  упирается в остаток → входит → корзины объединены → удаление и очистка. Ответы сверяются
  с типом фронта `CartSnapshot`.
- Запросы с побочными эффектами в локальный Битрикс не отправляются; эталонных ответов
  корзины от него нет.
- `GET /cart` добавляется в нагрузочный прогон.
