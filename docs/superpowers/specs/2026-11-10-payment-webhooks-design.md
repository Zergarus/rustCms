# Вебхуки и сверка платежей

Оплата подтверждается только пока открыта страница и идёт опрос
`payment-channel`. Закрыл вкладку — заказ может остаться неоплаченным, хотя
деньги прошли. Закрываем это двумя механизмами: уведомление от провайдера и
фоновая сверка.

## Принцип из Битрикса, который переносим

Тело уведомления **не является доказательством оплаты**: колбэк открыт наружу, и
прислать «оплачено» может кто угодно, зная id платежа. Тело используется только
чтобы понять, о каком платеже речь; факт оплаты подтверждается отдельным
запросом к провайдеру, а сумма сверяется — иначе частично оплаченный или
подменённый заказ закрылся бы как оплаченный.

## Маршрут

`POST /payment/webhook/{code}` — публичный, `code` — `pay_systems.code`
(`yookassa`, `alfa_sbp`, …). Ответ `{ "success": true }` при успехе; провайдер
повторяет при ошибке.

Порядок: найти активную платёжную систему по коду → найти `PaymentExtension` по
её id → `provider.webhook(...)` (проверка подписи и разбор тела — код проекта)
возвращает id нашего платежа → загрузить платёж и заказ → `provider.status(...)`
→ отметить оплату только если `paid` **и** сумма совпала → 200.

Идемпотентность: повторное уведомление и уже оплаченный платёж дают 200 без
побочных эффектов. Неизвестный код, неизвестный платёж, чужой провайдер —
безопасная ошибка без деталей; подпись/секрет проверяет проект.

## Трейты

- `PaymentProvider::webhook(state, payload: &Value, headers: &HeaderMap)
  -> Result<PaymentWebhook, BxError>`, где `PaymentWebhook { payment_id: i64 }`
  (`external_id` не нужен: ищем свой платёж по id, который положил `start`).
  Метод обязательный: без него платёжная система не получит уведомлений.
- `PaymentState` получает `amount: Option<f64>` — сумма, которую подтвердил
  провайдер. Ядро сверяет её с `payments.sum` (допуск 1 копейка); `None` —
  сверять нечего, доверяем `paid` (для провайдеров без суммы).

## Сверка

`payment::reconcile(state)` — раз в 10 минут (фоновая задача как
`currency::auto::spawn`): берёт неоплаченные платежи заказов за последние 30
дней (не отменённых), не больше 50 за проход, и для каждого с провайдером
вызывает `status`; `paid` и совпавшая сумма помечают заказ оплаченным тем же
путём, что `payment-channel`. Ошибки провайдера логируются и не останавливают
проход.

## Файлы

- `src/bxapi/project/mod.rs` — `PaymentWebhook`, `webhook`, `amount`.
- `src/payment.rs` — вебхук, сверка, общая `apply_status`.
- `src/bxapi/mod.rs` — маршрут `/payment/webhook/{code}` (public, без bxapi-обёртки? нет — с обёрткой, как остальное).
- `src/main.rs` — запуск фоновой сверки.
- `src/payment_tests.rs` — тесты.
