# Склады: штрихкоды и партии (5б-1) — дизайн

Дата: 2026-10-29. Подпроект 5б-1 серии «до функционала Битрикса „Бизнес“»
(… → валюты → склады: ядро (5а) → **склады: штрихкоды и партии (5б-1)** → склады: API-ключи и
API склада (5б-2) → SEO и поиск).

CMS — универсальный шаблон под любой проект (как сам Битрикс). Объём и поведение задаёт паритет с
модулем `catalog` Битрикса. Источники:
- штрихкоды: `b_catalog_store_barcode`, `b_catalog_docs_barcode`, `BARCODE_MULTI`;
  `Document\Action\Barcode\AddStoreBarcodeAction`, `DeleteStoreBarcodeAction`,
  `CCatalogDocsTypes::checkDocumentBarcodes`; отгрузка — `b_sale_store_barcode`,
  `Sale\Internals\Catalog\Provider` (проверки `DDCT_DEDUCTION_*`);
- партии: `b_catalog_store_batch`, `b_catalog_store_batch_docs_element`,
  `Store\Batch\Action\*` (`UpsertStoreBatchAction`, `ReduceStoreBatchAmountAction`,
  `MoveStoreBatchAction`), `Store\Batch\Trait\DistributionStrategy` (`DeductDocument`,
  `ShipmentStore`), `CostPriceCalculator`, `ProductBatchConverter` и `Balancer`;
- опция `catalog.cost_price_calculation_method`, установка — `CatalogSettings`
  (только при `!State::isProductBatchMethodSelected()`).

Строится поверх 5а (`src/stock`: документы, отгрузка, резерв). Спека 5а:
`docs/superpowers/specs/2026-10-27-stores-design.md`.

## Цель и критерии успеха

Магазин, как Битрикс:
- хранит штрихкоды товаров; поштучный товар учитывается по штрихкоду каждой единицы через
  документы склада и отгрузку;
- при выбранном методе (FIFO или средняя) ведёт партии и считает себестоимость отгрузок и маржу
  заказа.

Готово, когда:
- **Регрессия.** На копии основной базы, где метод не выбран и поштучных товаров нет, сборки до и
  после подпроекта дают байт в байт одинаковые ответы bxapi и `/api/v1`: каталог, поиск, корзина,
  оформление заказа. Проведение документов даёт те же остатки.
- **Сквозная проверка** на копии с переносом трансопта:
  1. выбор FIFO;
  2. два прихода одного товара по разным ценам;
  3. заказ;
  4. отгрузка: себестоимость по FIFO, маржа видна в заказе;
  5. снятие отгрузки возвращает количество в партию;
  6. поштучный товар: приход со сканированием штрихкодов, отгрузка с ними, поиск по штрихкоду в
     палитре.
- **Локальный Битрикс:** к нему идут только SELECT.

У трансопта в Битриксе: 1 строка в `b_catalog_store_barcode`, 0 партий, 0 поштучных товаров,
метод не выбран. Подпроект нужен шаблону, трансопт поведения не меняет.

## Вне объёма

- API-ключи и API склада — 5б-2.
- Обмен с 1С не меняется: штрихкод из 1С пишется в поле `CML2_BAR_CODE`, как в Битриксе. Партии
  обмен не трогает.
- Смена метода после выбора — запрещена, как в Битриксе.
- Себестоимость в публичном API и в выгрузке заказов в 1С.

## 1. Штрихкоды

### Данные

| Таблица | Аналог Битрикса | Что хранит |
|---|---|---|
| `catalog_barcodes` | `b_catalog_store_barcode` | товар, штрихкод (уникален во всей базе), склад, заказ, кто и когда создал и изменил. Пустой склад — общий штрихкод товара. |
| `catalog_products.barcode_multi` | `BARCODE_MULTI` | флаг «поштучный учёт», по умолчанию выключен |
| `store_document_barcodes` | `b_catalog_docs_barcode` | штрихкоды строки документа |
| `shipment_item_barcodes` | `b_sale_store_barcode.BARCODE` | штрихкоды единиц в отгрузке, по складу отгрузки позиции |

### Обычный товар

- Общие штрихкоды правятся в карточке товара. Один штрихкод не может быть у двух товаров:
  «Штрихкод X, введенный для товара Y, уже существует.»
- Штрихкоды в строке документа необязательны. При проведении они добавляются товару как общие
  (склад пустой), если такого штрихкода ещё нет.

### Поштучный товар

Действует только при включённом складском учёте; без него флаг хранится, но проверки не
выполняются.

При проведении в каждой строке поштучного товара должно быть ровно столько штрихкодов, сколько
единиц. Ошибки (тексты из языковых файлов Битрикса, `#…#` подставляются):
- число не совпадает — `CATALOG_STORE_DOCS_ERR_BAD_BARCODE_COUNT` и
  `WRONG_POSITION_BARCODES_COUNT`;
- штрихкод у другого товара — `WRONG_BARCODES_PRODUCT_ID`;
- штрихкода нет на складе-источнике — «На складе #STORE# нет товара #PRODUCT# со штрихкодом
  #BARCODE#».

| Документ | Проведение | Отмена проведения |
|---|---|---|
| Приход, оприходование, возврат | штрихкоды привязываются к складу-получателю | штрихкоды удаляются |
| Перемещение | штрихкод должен лежать на складе-источнике, затем переходит на склад-получатель | переходит обратно на склад-источник |
| Списание | штрихкод должен лежать на складе-источнике, затем запись штрихкода удаляется (как в Битриксе) | запись восстанавливается на складе-источнике по штрихкодам строки |

Всё в той же транзакции, что и проведение 5а: ошибка по любой строке откатывает документ целиком.

### Отгрузка

На вкладке «Отгрузка» карточки заказа у поштучной позиции для каждого склада отгрузки
указываются штрихкоды единиц. При «Отгружено»:
- штрихкода нет — «У товара "#PRODUCT_NAME#" не указан штрихкод.»;
- штрихкода нет на этом складе — «Для товара #PRODUCT_NAME# (##PRODUCT_ID#) не найден штрихкод
  "#BARCODE#".»;
- иначе штрихкод снимается со склада и привязывается к заказу (`catalog_barcodes.order_id`).

Снятие «Отгружено» возвращает штрихкоды на склад, заказ отвязывается. Ошибка по любой позиции
отменяет всю отгрузку, как в 5а.

### Поиск по штрихкоду

Точное совпадение сначала в `catalog_barcodes`, затем в поле `CML2_BAR_CODE`. Используется:
- в палитре Ctrl+K;
- в поле сканирования документа склада и отгрузки;
- в 5б-2 — в API.

## 2. Партии и себестоимость

### Данные

| Таблица | Аналог Битрикса | Что хранит |
|---|---|---|
| `catalog_store_batches` | `b_catalog_store_batch` | товар, склад, остаток партии, закупочная цена и валюта, дата создания |
| `store_batch_moves` | `b_catalog_store_batch_docs_element` | ссылка на партию; ссылка на строку документа **или** на строку склада отгрузки; количество (плюс — приход в партию, минус — расход); цена и валюта партии на момент движения |

- `shipment_item_stores` получает суррогатный ключ `id` (новой миграцией), чтобы на строку
  склада отгрузки могли ссылаться движения партий. Составной ключ остаётся уникальным.
- Опция `catalog.cost_price_calculation_method`: пусто (по умолчанию), `fifo` или `average`.
  Выбирается в настройках каталога при включённом складском учёте **один раз**: после выбора
  поле только для чтения, сервер отклоняет смену.

### Перестройка при выборе метода

Аналог `ProductBatchConverter` и `Balancer`.
- Если партий ещё нет, фоновая задача строит их по истории, по 100 товаров за шаг.
- История товара — проведённые документы по дате проведения и отгруженные позиции заказов по
  дате отгрузки, применяются по правилам ниже по порядку.
- Пока задача идёт, настройки показывают «Партии перестраиваются: N из M». Задача
  возобновляется после перезапуска сервера.

### Правила

| Операция | FIFO | Средняя |
|---|---|---|
| Проведение прихода, оприходования, возврата | новая партия на строку с ценой строки в валюте документа | одна партия на товар и склад; цена — средневзвешенная (с переводом валюты), округление до 2 знаков |
| Отмена проведения прихода, оприходования, возврата | партия удаляется; уже израсходованное из неё переносится на другие партии склада (`rebindWriteOffValues`) | из партии вычитается количество строки, цена пересчитывается |
| Списание, перемещение (источник), отгрузка | расход из партий склада от старых к новым (по `id`) | расход из единственной партии склада |
| Перемещение (получатель) | каждая израсходованная часть становится партией получателя со своей ценой | вливается в партию получателя с пересчётом цены |
| Отмена проведения списания и перемещения, снятие «Отгружено» | количество возвращается в те же партии | то же, с пересчётом средней цены |

**Нехватка партий.** Если в партиях меньше товара, чем расходуется, расходуется сколько есть
(так бывает, когда 1С меняет остатки мимо документов). Непокрытая часть ни к какой партии не
привязывается, как в Битриксе.

### Себестоимость

Себестоимость единицы отгруженной позиции =
(Σ количество × цена партии по её движениям + непокрытое количество × закупочная цена товара) /
количество. Всё переводится в валюту заказа по курсам модуля валют.

- В Битриксе себестоимость нигде не показывается, поэтому правило для непокрытой части — наше:
  маржа всегда посчитана.
- Метод не выбран — оценка по закупочной цене товара (как `calculate()` Битрикса без метода) с
  пометкой «по закупочной цене».
- Маржа заказа = сумма позиций − себестоимость позиций. Доставка в маржу не входит.

**Без выбранного метода** партий нет, проведение и отгрузка работают как в 5а.

## 3. Админка

Новые блоки встают в нынешние формы на оболочке этапа 1. Перевод карточек на вкладки — этап 2
редизайна, не здесь.

### Право

Новое право `catalog.purchase_info` — «Видеть закупочные цены и себестоимость» (аналог
`catalog_purchas_info`).
- Под ним: закупочная цена в карточке товара, себестоимость и маржа в заказе, партии и стоимость
  остатков.
- Миграция выдаёт право всем группам, у которых есть `collections.manage` или `shop.manage`:
  сегодня ни у кого ничего не пропадает.
- Цены в документах склада по-прежнему видны по `shop.manage`: без них документ не оформить.

### Карточка товара, блок «Торговый каталог»

- Флажок «Поштучный учёт (уникальный штрихкод у каждой единицы)». Пока по складам есть
  штрихкоды единиц, флажок не снимается: «У товара есть штрихкоды единиц на складах».
- Общие штрихкоды — список, по одному в строке, с добавлением и удалением.
- У поштучного товара — только чтение: сколько штрихкодов на каком складе и ссылка на полный
  список.

### Документ склада

- Над строками поле «Сканировать штрихкод». Сканер вводит код и Enter:
  - найден товар без строки в документе — добавляется строка;
  - строка уже есть — +1 к количеству, у поштучного товара ещё и штрихкод в строку;
  - не найден — красное уведомление.
- В строке кнопка «Штрихкоды 3/5» раскрывает список, по одному в строке. Если у поштучного
  товара число не совпадает с количеством, счётчик красный. Проверку при проведении это не
  заменяет.
- У проведённого документа штрихкоды только для чтения.

### Карточка заказа

- **«Отгрузка».** У поштучных позиций на каждый склад отгрузки — поле штрихкодов со счётчиком
  «2/3» и полем сканирования. Сохраняется той же панелью «Сохранить» и Ctrl+S.
- **«Состав»**, с правом `catalog.purchase_info`: колонки «Себестоимость» и «Маржа».
  - до отгрузки — оценка: по партиям склада (FIFO — по очереди, средняя — по цене партии), без
    метода — по закупочной цене; подписано «оценка»;
  - после отгрузки — фактическая, по движениям партий.
- **Боковая колонка:** «Маржа заказа: сумма (процент)».

### «Остатки»

- При выбранном методе — колонка «Стоимость» (остаток × цена партий) и итог по фильтру.
- Ссылка с товара открывает страницу партий: склад, дата, документ-источник, было, осталось,
  цена; у каждой партии — её движения со ссылками на документы и заказы.
- Если партии покрывают не весь остаток склада — пометка «партии покрывают 40 из 50».

### Настройки каталога

- «Метод расчёта себестоимости: не выбран / FIFO / Средняя». При сохранении подтверждение:
  «Метод выбирается один раз, сменить его потом будет нельзя». После выбора поле только
  показывает метод.
- Статус перестройки партий.

### Палитра Ctrl+K

Ввод, похожий на штрихкод, ищет товар точным совпадением и ставит его первым в группе «Записи».

## 4. Перенос из Битрикса

`cms import-bitrix` дополнительно переносит:
- **`b_catalog_product.BARCODE_MULTI`**;
- **`b_catalog_store_barcode`** со складом; `ORDER_ID` не переносится — заказы Битрикса не
  переносятся;
- **`b_catalog_docs_barcode`** с привязкой к перенесённым строкам документов;
- **`b_option` `catalog.cost_price_calculation_method`**: выбранный в Битриксе метод у нас тоже
  считается выбранным;
- **`b_catalog_store_batch`** как есть: остаток, закупочная цена, валюта;
- **`b_catalog_store_batch_docs_element`**: только движения по строкам документов. Движения по
  отгрузкам (`SHIPMENT_ITEM_STORE_ID`) пропускаются с предупреждением; остаток партии берётся из
  Битрикса, где они уже учтены.

Правила:
- Строки с несуществующим товаром, складом или строкой документа пропускаются с предупреждением
  в лог.
- Дубль штрихкода: первый сохраняется, остальные пропускаются с предупреждением.
- Повторный перенос заменяет штрихкоды и партии целиком.
- Метод выбран, а партий нет — после переноса запускается перестройка, как при выборе метода.

## Проверка

- **Модульные тесты:**
  - FIFO и средняя: приход, списание, возврат, перемещение, отмена прихода с перепривязкой
    расхода;
  - нехватка партий: непокрытая часть без партии, себестоимость по закупочной цене;
  - округление средней цены.
- **`sqlx::test`:**
  - штрихкоды: проведение и отмена всех типов для обычного и поштучного товара; число
    штрихкодов ≠ количеству; штрихкод чужого товара; штрихкод не на том складе; дубль;
  - отгрузка поштучного товара: нет штрихкода, чужой штрихкод; снятие отгрузки возвращает
    штрихкод на склад;
  - партии: выбор метода и запрет смены; перестройка по истории; себестоимость и маржа заказа
    (оценка до отгрузки, факт после); стоимость остатков;
  - право `catalog.purchase_info`: без него закупочные цены, себестоимость и маржа скрыты везде;
  - перенос из Битрикса по всем таблицам выше.
- **Сквозная проверка** — по списку из «Цели».
- **Регрессия** — bxapi и `/api/v1` байт в байт на базе без метода и без поштучных товаров.
- **Локальный Битрикс:** запросы с побочными эффектами не отправляются.
