# Обмен с 1С: каталог — дизайн

Дата: 2026-10-10. Подпроект 2а серии «до функционала Битрикса „Бизнес“»
(коллекции → SKU → **обмен с 1С: каталог** → обмен с 1С: заказы (2б) → скидки → …).
Опирается на коллекции (`2026-10-09-collections-rename-design.md`) и торговые
предложения (`2026-10-09-sku-design.md`).

## Цель и критерии успеха

1С обменивается каталогом с CMS так же, как с Битриксом: в настройках обмена 1С
меняется только адрес сайта. Пакеты приходят по протоколу `1c_exchange.php` в форматах
CommerceML 3.1 (пакетами по типам файлов) и классическом CommerceML 2.x
(`import.xml` + `offers.xml`).

Готово, когда:

- реальные пакеты трансопта (`sites/transopt.local/Exchange_Песочница_2026-08-20`,
  `Exchange_Номенклатура_2026-09-29`), отправленные по протоколу, принимаются с ответом
  `success` и раскладываются в разделы, поля, записи, цены и остатки; выборка товаров
  совпадает с данными Битрикса трансопта (расхождения разобраны в отчёте);
- повторная отправка того же пакета не создаёт дублей записей и файлов;
- товары с характеристиками (`Ид` вида `товар#характеристика`) становятся торговыми
  предложениями;
- фронт трансопта и bxapi на основной dev-базе работают без изменений.

Не входит: обмен заказами (2б), выгрузка каталога из CMS в 1С (`type=get_catalog`),
справочник единиц измерения, НДС и наценки (подпроект «Торговый каталог»).

## Протокол

Адрес: `/bitrix/admin/1c_exchange.php` (как у Битрикса) и `/api/1c/exchange`. Параметры
запроса `type` и `mode`, ответы — текст `text/plain; charset=utf-8`, строки через `\n`.

| Запрос | Ответ |
|---|---|
| `type=catalog&mode=checkauth` | HTTP Basic: пользователь CMS с правом `exchange.1c` (или суперадмин). `success\nCMS_1C_SID\n<токен>`; без права — `failure\n<текст>`. |
| `mode=init` | `zip=yes|no\nfile_limit=<байты>\nsessid=<токен>\nversion=3.1` |
| `mode=file&filename=<путь>` | Тело дописывается к файлу `upload/1c_exchange/<сессия>/<путь>`. `success`. |
| `mode=import&filename=<файл>` | Распаковка zip при первом обращении, разбор файла. `progress\n<этап>` (следующий вызов продолжает) или `success\n<итог>`; ошибка — `failure\n<текст>`. |
| `mode=deactivate` | После полной выгрузки (`СодержитТолькоИзменения="false"`): действие над записями и разделами, не пришедшими в сессии. `success`. |
| `mode=complete` | Завершение сессии: запись в журнал, очистка каталога сессии. `success`. |

- Сессия обмена — таблица `exchange_sessions` (токен — sha256 в БД, пользователь,
  создана, последняя активность, каталог, состояние шагов по файлам, множество
  `xml_id`, пришедших в полной выгрузке). 1С возвращает токен в cookie `CMS_1C_SID`.
  Срок жизни — 24 часа с последней активности; каталоги старых сессий удаляются при
  следующем `checkauth`.
- Шаг `import` укладывается в интервал из настроек (по умолчанию 30 с). Состояние шага
  (файл, обработано объектов) хранится в сессии; обычный файл обрабатывается за один
  вызов. Импорт одного файла (или одного шага) — одна транзакция.
- Ограничения: `file_limit` из настроек (по умолчанию 200 МБ на файл); суммарный
  распакованный размер архива — не больше 2 ГБ и не больше 100 000 записей архива;
  пути `filename` и записей zip — только внутри каталога сессии (`..`, абсолютные пути,
  ссылки — отказ).
- Кодировка: UTF-8 (с BOM и без) и windows-1251 по объявлению в `<?xml … encoding>`.
- Тип файла определяется по содержимому: `Классификатор` с `Группы`/`Свойства`/
  `ЕдиницыИзмерения`/`Склады`/`ТипыЦен`, `Каталог` с `Товары`, `ПакетПредложений` с
  `Цены`/`Остатки`/полными `Предложения` (2.x).

## Данные — миграция `0017_exchange.sql`

- `xml_id TEXT NOT NULL DEFAULT ''` у `collections`, `collection_fields`, `catalog_stores`,
  `catalog_price_types`; уникальные индексы по непустому `xml_id` (у полей — в пределах
  коллекции, у вариантов уже есть `(field_id, xml_id)`).
- `files.sha256 TEXT NOT NULL DEFAULT ''` + индекс; заполняется при сохранении файла,
  для существующих — при первом сравнении.
- `exchange_sessions`, `exchange_log` (время, пользователь, режим, файл, итог,
  `created/updated/deactivated` по типам объектов, ошибка, длительность).
- Право `exchange.1c` «Обмен с 1С» в `access.rs`.

Импорт из Битрикса переносит XML_ID инфоблоков, свойств, складов, типов цен и опции
`catalog/1C_*` → настройки обмена.

## Сопоставление

Всё — по `xml_id` = `Ид` 1С.

- **Каталог/Классификатор** → коллекция с каталогом: по `xml_id`; иначе коллекция из
  настройки «Коллекция по умолчанию» (ей присваивается `xml_id`); иначе новая (название из
  пакета, код транслитом, каталог включён).
- **Группы** → разделы (дерево, название, сортировка в порядке пакета). `ПометкаУдаления`
  и отсутствие в полной выгрузке → действие «Разделы» из настроек: ничего / деактивировать /
  удалить.
- **Свойства** → поля: `Справочник` → `list` с вариантами из `ВариантыЗначений`
  (`xml_id` варианта = `ИдЗначения`), `Строка` → `string` (многострочное значение — `text`,
  если поле уже `text`), `Число` → `number`, `Дата` → `date`; `Множественное` → `multiple`.
  Код нового поля — транслит названия (уникальный в коллекции). Значение справочника, не
  найденное среди вариантов, добавляется вариантом.
- **Системные поля** (создаются при первой надобности; если у коллекции уже есть поле с
  таким `xml_id` — используется оно, например `MORE_PHOTO` с `xml_id` `CML2_PICTURES` у
  трансопта):

  | `xml_id` | код | вид |
  |---|---|---|
  | `CML2_ARTICLE` | `cml2_article` | string |
  | `CML2_BAR_CODE` | `cml2_bar_code` | string |
  | `CML2_MANUFACTURER` | `cml2_manufacturer` | list (вариант по `Изготовитель/Ид`) |
  | `CML2_TRAITS` | `cml2_traits` | string, множественное («Название: значение») |
  | `CML2_TAXES` | `cml2_taxes` | string, множественное («НДС: 20») |
  | `CML2_BASE_UNIT` | `cml2_base_unit` | string (код единицы) |
  | `CML2_PICTURES` | `cml2_pictures` | file, множественное |
  | `CML2_FILES` | `cml2_files` | file, множественное |

  Все `Картинка` товара — в `cml2_pictures` (в порядке пакета); первая дополнительно
  становится детальной и превью-картинкой записи (как в Битриксе).
- **Единицы** → только код в `cml2_base_unit`.
- **Склады** → `catalog_stores` по `xml_id` (новый — с названием из пакета, активный).
- **Типы цен** → `catalog_price_types` по `xml_id` (новый — с названием; валюта из
  пакета; базовым не становится).
- **Товары** → записи по `xml_id`: название; код — транслит при добавлении и (если
  включено) при обновлении; `Описание` → детальный текст; раздел — первая группа; поля;
  картинки и файлы; вес из `ЗначенияРеквизитов` «Вес» (в граммах; если в кг — ×1000) →
  `catalog_products.weight`. `ПометкаУдаления` и отсутствие в полной выгрузке → действие
  «Записи» из настроек: ничего / деактивировать / удалить. Новая запись активна.
- **Предложения** (`ПакетПредложений`):
  - `Ид` без `#` — цены и остатки самого товара;
  - `Ид` вида `товар#характеристика` — торговое предложение: при включённой настройке
    «Использовать торговые предложения» у коллекции создаётся коллекция предложений
    (подпроект SKU), предложение — запись с `xml_id` = полный `Ид` и `product_id` = товар;
    `ХарактеристикиТовара` → поля-строки предложений с флагом `offer_tree`; при
    выключенной настройке такие предложения пропускаются с записью в журнал.
  - `Цены` → `catalog_prices` по типу цены (замена цен этого типа у записи);
  - `Остатки` → `catalog_store_amounts` по складу, `catalog_products.quantity` = сумма;
  - «Деактивировать товары без цены» (настройка): запись без цен после пакета цен
    становится неактивной.
- **Файлы**: перед сохранением считается sha256; если у этой записи в этом поле (или в
  её картинках) уже есть файл с тем же sha256, остаётся прежний `file_id`, новый не
  создаётся. Ссылки на файлы, отсутствующие в пакете, пропускаются (значение поля не
  трогается).

## Настройки (`options`, модуль `exchange`) и админка

Страница «Обмен с 1С» (право `exchange.1c`): «Коллекция по умолчанию»; «Разделы» и
«Записи»: ничего / деактивировать / удалить; транслит кода при добавлении / при
обновлении; использовать торговые предложения; деактивировать товары без цены;
интервал шага (с); лимит размера файла; использовать zip. Ниже — журнал последних
50 обменов.

## Проверка

- Модульные тесты разбора на фикстурах в `tests/fixtures/1c/` (рукописные, без
  реальных данных): каждый тип файла 3.1, `import.xml`/`offers.xml` 2.x, справочник,
  множественные значения, пометка удаления, предложение с `#` и характеристиками,
  windows-1251, BOM, картинки.
- `sqlx::test` сопоставления: создание и обновление разделов, полей, вариантов, записей,
  цен, остатков, складов, типов цен; действия при пометке удаления и полной выгрузке;
  повтор пакета без изменений; файл с тем же sha256 не дублируется; SKU-предложения.
- Тесты протокола через роутер: `checkauth` с правом / без / неверный пароль; `init`;
  `file` частями и zip; `import` → `success`; путь с `..` → `failure`; zip сверх лимита →
  `failure`; истёкшая сессия.
- Сквозной прогон: оба реальных пакета трансопта, отправленные curl по протоколу,
  на копии dev-базы (`CREATE DATABASE … TEMPLATE`); сверка выборки (50 товаров: название,
  раздел, цены по типам, остатки по складам, поля) с Битриксом трансопта; повторный прогон
  без дублей; время обработки — в отчёт.
- Регрессия на основной dev-базе: фронт трансопта, ответы bxapi байт в байт.
- В локальный Битрикс запросы с побочными эффектами не отправляются.
