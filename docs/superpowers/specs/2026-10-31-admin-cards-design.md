# Админка, этап 2: карточки на вкладках и быстрый просмотр — дизайн

Дата: 2026-10-31. Продолжение редизайна админки (этап 1 — оболочка:
`docs/superpowers/specs/2026-10-28-admin-shell-design.md`, в `main`). Стиль — Linear/Notion,
без отдельного фронтенд-проекта: MiniJinja, HTMX, чистый JS (`static/admin/admin.js`).

## Цель и критерии успеха

Длинные карточки в одну колонку разбить на вкладки так же, как карточка заказа этапа 1; дать
быстрый просмотр заказа и товара из списков. Серверная логика сохранения и API сайта не
меняются.

Готово, когда:
- четыре карточки (товар, пользователь, коллекция, скидка) на вкладках по разделу 2;
- красная точка на вкладке с ошибкой, карточка открывается на первой такой вкладке;
- панель быстрого просмотра в списках заказов и записей коллекций с каталогом по разделу 3;
- ручная проверка в браузере по разделу 4 пройдена;
- регрессия: ответы `/api/v1` и bxapi байт в байт как до этапа; новых зависимостей нет.

## Вне объёма

- J/K, сохранённые виды, фильтры-чипы, правка в таблице, массовые действия — этап 3.
- Быстрый просмотр пользователей, коллекций, скидок.
- Изменения логики сохранения, проверок и API сайта.

## 1. Общая механика вкладок карточки

- **Разметка.** Макрос `tabs` в `templates/admin/_ui.html` расширяется для вкладок внутри
  одной формы: ключ, название, необязательный счётчик, признак ошибки. Вкладка —
  `<section data-tab="<ключ>">`. Сервер отдаёт все вкладки сразу, видна одна.
- **Переключение** в `admin.js`, без запроса: активная вкладка — в адресе `?tab=<ключ>`
  (`history.replaceState`); клик и клавиши `[` / `]`; неизвестный ключ — первая вкладка.
  Запись карточки в строке открытых записей (этап 1) помнит последнюю вкладку, как у заказа.
- **Сохранение.** Одна форма на карточку; панель «Есть несохранённые изменения → Сохранить» и
  Ctrl+S как сейчас; точка «изменено» на вкладке с несохранёнными правками; после успешного
  сохранения — та же вкладка и уведомление «Сохранено». Вкладки со своими действиями
  («Предложения» товара, «Поля» и «Предложения» коллекции, «API-ключи» и «Заказы»
  пользователя) лежат вне основной формы: панель «Сохранить» к ним не относится.
- **Ошибки.** Проверки на сервере возвращают список `(вкладка, текст)`. Карточка открывается
  на первой вкладке с ошибкой; у каждой такой вкладки красная точка; тексты — наверху своей
  вкладки. Ошибки без вкладки — над вкладками.
- **Права и видимость.** Вкладка без прав или без данных не показывается; правила видимости
  полей внутри — прежние.
- **Узкий экран.** Строка вкладок прокручивается горизонтально.

## 2. Вкладки карточек

**Товар (запись коллекции)**, `/admin/items/{id}`

| Ключ | Вкладка | Содержимое | Когда видна |
|---|---|---|---|
| `main` | Основное | название, код, раздел, внешний код, активность, сортировка, дата публикации | всегда |
| `text` | Описание | анонс, детальный текст | всегда |
| `fields` | Поля | поля коллекции, файлы | у коллекции есть поля |
| `catalog` | Каталог | тип, цены, остатки, поштучный учёт и штрихкоды, закупочная цена (право `catalog.purchase_info`) | у коллекции включён каталог |
| `offers` | Предложения | список и генератор, свои кнопки | товар с предложениями |

**Пользователь**, `/admin/users/{id}`

| Ключ | Вкладка | Содержимое |
|---|---|---|
| `profile` | Профиль | логин, имя, e-mail |
| `access` | Доступ | суперадминистратор, активность, группы |
| `password` | Пароль | смена пароля |
| `keys` | API-ключи | список, выпуск, отзыв, свои кнопки; право `users.manage` |
| `orders` | Заказы | последние 20 заказов пользователя со ссылками, только чтение; право `orders.manage` |

**Коллекция**, `/admin/collections/{id}`

| Ключ | Вкладка | Содержимое |
|---|---|---|
| `settings` | Настройки | название, код, описание, сортировка, флажки |
| `fields` | Поля | таблица полей и форма добавления, свои кнопки |
| `offers` | Предложения | режим торговых предложений, своя кнопка |

**Скидка**, `/admin/discounts/{id}`

| Ключ | Вкладка | Содержимое |
|---|---|---|
| `main` | Основное | название, активность, период, приоритет, сортировка, флажки |
| `conditions` | Условия | дерево условий |
| `actions` | Действия | дерево действий |
| `groups` | Группы | группы пользователей |
| `coupons` | Купоны | ссылка на страницу купонов со счётчиком; если включены купоны |

- **Удаление.** Блоки «Удаление» внизу страниц заменяет кнопка «Удалить» в шапке карточки; то
  же подтверждение и тот же обработчик.
- **Новая запись.** Только вкладки основной формы; после создания — карточка с полным
  набором.

## 3. Быстрый просмотр

Списки: заказы (`/admin/shop/orders`) и записи коллекций с каталогом
(`/admin/collections/{id}/items`).

- **Открытие.** Клик по строке вне ссылок и кнопок — панель справа (~420 px), список на месте;
  клик по названию/номеру — карточка; Ctrl/Cmd-клик — новая вкладка браузера; Esc или
  крестик — закрыть; клик по другой строке — смена содержимого; строка с панелью подсвечена;
  на узком экране панель во весь экран; в строку открытых записей панель не попадает.
- **Адреса.** `GET /admin/shop/orders/{id}/peek`, `GET /admin/items/{id}/peek` — HTML-фрагмент
  через htmx; права как у карточки (`orders.manage` / доступ к коллекции), иначе 403.
- **Заказ:** номер, дата, покупатель, телефон, e-mail; сумма; до 5 позиций с количеством и «ещё
  N»; статус, оплата, отгрузка, доставка. Действия: смена статуса и «Оплачен / Не оплачен» —
  существующие обработчики `/status` и `/paid`, ответом для запроса из панели — обновлённая
  панель и строка списка; ошибка — красное уведомление. Кнопка «Открыть карточку».
- **Товар:** картинка, название, код, раздел; цена базового типа; остатки по складам и
  доступное количество; активность. Действие: переключатель «Активен» — новый
  `POST /admin/items/{id}/active` (право записи в коллекцию), строка списка обновляется. Кнопка
  «Открыть карточку».

## 4. Проверка

- **`sqlx::test`, HTTP:**
  - каждая карточка: состав вкладок, скрытие без прав или данных; `?tab=` и неизвестный
    ключ; сохранение с ошибкой — первая вкладка с ошибкой, точки, тексты на своих вкладках;
    успешное сохранение — та же вкладка и уведомление;
  - табличный тест: каждая проверка товара, пользователя, коллекции и скидки помечена своей
    вкладкой;
  - новая запись — только вкладки основной формы;
  - панели: фрагменты, 403 без прав, статус и оплата из панели, ошибка оплаты отменённого,
    `POST /admin/items/{id}/active` с правом и без;
  - кнопка «Удалить» в шапке делает то же, что старый блок.
- **Браузер:** четыре карточки и две панели — переключение кликом и `[` `]`, точка
  «изменено», Ctrl+S с любой вкладки, точка ошибки и открытие нужной вкладки, последняя
  вкладка из строки открытых записей, узкий экран.
- **Регрессия:** `/api/v1` и bxapi байт в байт; существующие тесты админки проходят, правки —
  только там, где проверялась разметка старых блоков.
