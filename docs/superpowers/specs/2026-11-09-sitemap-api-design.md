# SEO: sitemap-эндпоинты

Продолжение SEO по решению пользователя: robots.txt остаётся на стороне фронта
(статический `public/robots.txt`), CMS отдаёт только sitemap. Фронт собирает
`/sitemap.xml` и `/sitemap-{type}.xml` из двух эндпоинтов бэкенда, кеширует
ответы на час и при ошибке бэка отдаёт 503.

## Контракт

Снят с живого Битрикса 2026-11-09 (`https://transopt.local/api/v1/seo/sitemap`),
чтобы переключение `API_BASE_URL` на CMS не меняло поведение витрины.

`GET /api/v1/seo/sitemap` →

```json
{"status": "success", "data": {"items": [{"type": "products", "count": 4330, "lastmod": "2026-08-26T11:19:28+00:00"}]}, "errors": []}
```

`GET /api/v1/seo/sitemap/{type}` →

```json
{"status": "success", "data": {"type": "products", "items": [{"path": "/product/38382/", "lastmod": "2026-05-07T13:35:15+00:00"}]}, "errors": []}
```

`lastmod` — RFC3339 с `+00:00`; в индексе `null`, если записей у типа нет.
Неизвестный `type` — 404 в обычном формате ошибок API
(`{"error": "not_found", "message": "not found"}`).

## Типы и источники

| type | коллекция | путь | записей (сверено с Битриксом) |
|---|---|---|---|
| products | `catalog` | `/product/{code или id}/` | 4330 |
| catalog | — (отключён) | — | 0 |
| news | `info` | `/news/{code}/` | 143 |
| schemes | `schemes` | `/schemes/{code}/` | 421 |
| contacts | `contacts`, если появится | `/contacts/{id}/` | 0 |

`catalog` сознательно отдаётся пустым: адреса `/catalog/{slug}/` строит
`slugifyMarkFamily` проекта, в CMS такой логики и данных нет. Фронт выкидывает
типы с `count = 0`, поэтому `/sitemap-catalog.xml` просто не попадёт в индекс,
как уже сейчас происходит с `contacts`. Порт slug семейств — отдельная задача.

`news` — коллекция `info`, а не `news`: витрина читает новости из
`/api/v1/iblock/info/element/list`, и Битрикс отдавал в этот тип ровно её записи.

## Правила

- Видимость как у публичного API: коллекция с `api_enabled`, запись `active` и с
  наступившей датой публикации (`published_at IS NULL OR published_at <= now()`).
  Разделы не фильтруются: у Битрикса в products 4330, а с фильтром по активным
  разделам — 4319.
- `products`: код записи в нижнем регистре; пустой код заменяется числовым id.
- `lastmod` записи — `updated_at`; для индекса — максимум по типу.
- Порядок типов в индексе фиксирован: products, catalog, news, schemes, contacts.
- Ответы не кешируются в CMS: фронт кеширует на час, запросы дешёвые.
- Существующие ответы (`/api/v1/seo/{kind}/{id}`, bxapi) не меняются.

## Альтернативы

- Все 5 типов, `catalog` из кодов разделов (`/catalog/#SECTION_CODE_PATH#/`) —
  532 адреса, которых нет на витрине, мусор в индексе; отклонено.
- Сначала портировать slug семейств — правильно по итогу, но блокирует весь
  sitemap; вынесено в отдельную задачу.
- Конфиг типов в `project/mod.rs` — отклонено на этом этапе: пять типов и их
  порядок — контракт фронта, а коды коллекций совпадают с api-кодами bxapi,
  которые уже зафиксированы контрактом. Если появится второй сайт с другими
  кодами, таблицу вынесем в проект.
