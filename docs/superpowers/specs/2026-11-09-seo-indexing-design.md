# SEO: canonical и индексация

Продолжение метаданных по разрешению пользователя «Давай дальше SEO».
Выбран существующий модуль SEO и отдельный API. Настройки во frontend отсутствуют:
Nuxt не входит в checkout.

Canonical — пусто либо явный абсолютный http(s) URL без credentials/fragment,
либо локальный путь с одним начальным слешем. Не наследуется и не раскрывает
переменные: одинаковый canonical у всех потомков опасен. Пусто означает, что
витрина сама использует URL текущей страницы. Пробелы/управляющие символы запрещены.
Максимум 2000 символов.

Robots: пусто (наследовать), index,follow; noindex,follow; index,nofollow;
noindex,nofollow. Наследование как у метаданных. По умолчанию index,follow.
API добавляет canonical и robots. Редактор показывает настройки и сохранённый
результат. Прежние права, видимость и защита Origin действуют.

Альтернативы: наследуемый canonical отклонён из-за склейки потомков; вычисление
URL по шаблонам Битрикса отложено до согласования маршрутов витрины. Sitemap и
импорт остаются следующими этапами. Изменение API аддитивное; фронтенд обязан
подключить новые поля, иначе они не влияют на HTML.

План: регрессионный HTTP-тест → миграция и модель → валидация/наследование →
редактор → полные тесты, clippy/fmt, сборка и локальный запуск.

## Проверка

HTTP-регрессия сначала падала: robots=null вместо noindex,follow. После реализации
прошли все 5 SEO-тестов. Независимое read-only ревью существенных замечаний не выявило.
Итог: cargo test — 1134 passed, clippy -D warnings, fmt --check и diff --check
успешны. Собранная версия запущена на 3000; GET SEO API проверен локально.
