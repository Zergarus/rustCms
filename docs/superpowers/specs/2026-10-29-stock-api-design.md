# Склады: API-ключи и API склада (5б-2) — дизайн

Дата: 2026-10-29. Подпроект 5б-2 серии «до функционала Битрикса „Бизнес“»
(… → склады: ядро (5а) → склады: штрихкоды и партии (5б-1) → **склады: API-ключи и API склада
(5б-2)** → SEO и поиск).

CMS — универсальный шаблон: одна установка — один проект. Аналог в Битриксе — модуль `rest`
(входящие вебхуки: пользователь + набор scope) и методы `catalog.document.*`,
`catalog.storeproduct.list`, `catalog.store.list`. Формат и адреса Битрикса не повторяем: свой
REST, ключ в заголовке.

## Цель и критерии успеха

Внешние системы (WMS, ТСД со сканерами, складские программы) работают со складом без входа в
админку: читают склады, остатки и товары, ведут документы и проводят их — по тем же правилам,
что админка (5а и 5б-1: проверки, штрихкоды, партии). API только вызывает функции `src/stock`.

Готово, когда:
- **Регрессия.** Ответы bxapi и `/api/v1` байт в байт как до подпроекта.
- **Сквозная проверка** на копии основной базы:
  1. администратор выпускает в админке ключ «ТСД» со scope `stock.read` и `stock.write`;
  2. через `curl` товар находится по штрихкоду, создаётся черновик прихода; повтор запроса с тем
     же `xml_id` не создаёт дубля;
  3. проведение этим ключом — 403;
  4. второй ключ со scope `stock.conduct` проводит документ: остатки и партии меняются как при
     проведении из админки;
  5. ключ «ТСД» отозван — следующий запрос 401.
- **Локальный Битрикс:** только SELECT (в подпроекте переноса из Битрикса нет).

## Вне объёма

- OAuth, приложения, вебхуки исходящие.
- Лимит частоты запросов (его нет во всём проекте).
- Общая страница всех ключей всех пользователей.
- OpenAPI-схема.
- Перенос внешнего кода документов из Битрикса: в `b_catalog_store_docs` его нет.
- API заказов и каталога — позже, на тех же ключах.

## 1. API-ключи

### Данные

Таблица `api_keys`:

| Поле | Что хранит |
|---|---|
| `id` | |
| `user_id` | владелец, `ON DELETE CASCADE` |
| `name` | название («WMS склад Новосибирск»), не пустое |
| `prefix` | 8 случайных символов `[a-z0-9]`, уникален — по нему ищется ключ |
| `secret_hash` | sha256 секрета (hex); сам секрет не хранится |
| `scopes` | `TEXT[]` из `stock.read`, `stock.write`, `stock.conduct`, не пустой |
| `expires_at` | срок; NULL — бессрочно |
| `created_by`, `created_at` | кто и когда выпустил |
| `last_used_at`, `last_used_ip` | последнее использование |
| `revoked_at` | когда отозван; отозванный ключ остаётся для истории |

Формат ключа: `cms_<prefix>_<секрет>`, секрет — 32 случайных символа `[A-Za-z0-9]` из
криптографического генератора. В логах, ответах и админке — только `cms_<prefix>_…`.

### Scope

| Scope | Что разрешает |
|---|---|
| `stock.read` | склады, остатки, поиск товара, чтение документов и поставщиков |
| `stock.write` | создание, правка, удаление черновиков документов и их штрихкодов; создание поставщиков |
| `stock.conduct` | проведение и отмена проведения |

Названия общие: будущие API получат свои scope (`orders.read` и т. п.).

### Проверка запроса

Extractor `ApiAccess`:
1. Ключ из `Authorization: Bearer <ключ>`.
2. Поиск по `prefix`; ключ не отозван и не просрочен; хэш секрета сравнивается за постоянное
   время.
3. Пользователь ключа активен (`users.active`); его права собираются так же, как при входе в
   админку (`Access`).
4. Метод требует scope и право пользователя; разрешено, только если есть оба.
5. Отказы:
   - нет ключа, неверный, просрочен, отозван, пользователь неактивен — 401
     `{"error":"unauthorized","message":"Неверный или отозванный API-ключ"}` и
     `WWW-Authenticate: Bearer`;
   - нет scope — 403 `{"error":"forbidden","message":"Нужен scope stock.conduct"}`;
   - нет права — 403 `{"error":"forbidden","message":"Нужно право shop.manage"}`.
6. `last_used_at` и `last_used_ip` пишутся не чаще раза в минуту на ключ.

### Админка

Блок «API-ключи» в карточке пользователя (`/admin/users/{id}`), право `users.manage`; ключи
суперадминистратора правит только суперадминистратор (как сейчас сам пользователь).
- Таблица: название, `cms_<prefix>_…`, scope, выпущен, последнее использование, срок; отозванные
  помечены «отозван».
- «Выпустить ключ»: название, флажки scope, необязательный срок (дата). После сохранения ключ
  показывается **один раз** с кнопкой «Копировать» и текстом «Сохраните ключ — потом его не
  показать».
- «Отозвать» — в два шага (второй POST с `confirm=1`), без `confirm()` браузера.

## 2. Методы API склада

Префикс `/api/stock/v1`. JSON; даты ISO 8601 (дата документа — `YYYY-MM-DD`), количества и цены
числами. Списки: `?limit=50&offset=0` (по умолчанию 50, максимум 500) → `{"items": [...],
"total": N}`. Всем методам нужно право `shop.manage`; со складским учётом выключенным методы
документов отвечают 409 `«Складской учёт выключен»`, как раздел документов в админке.

### Чтение — `stock.read`

| Метод | Ответ |
|---|---|
| `GET /stores` | `id`, `xml_id`, `name`, `address`, `active`, `is_default` |
| `GET /rests?item_id=1,2&store_id=3` | `item_id`, `store_id`, `amount`, `quantity_reserved`; без фильтров — все строки остатков постранично, порядок `item_id, store_id` |
| `GET /products/lookup?barcode=…` / `?xml_id=…` / `?id=…` | `id`, `xml_id`, `name`, `type` (`simple` / `offer`), `barcode_multi`, `barcodes` (общие), `stores` (`store_id`, `amount`, `quantity_reserved`); `purchasing_price`, `purchasing_currency` — только при праве `catalog.purchase_info`. Штрихкод ищется как `barcodes::find_item`. Ровно один параметр, иначе 400 |
| `GET /documents?type=A&status=Y&from=…&to=…&contractor_id=…&xml_id=…` | документы без строк: `id`, `xml_id`, `type`, `title`, `number`, `date`, `status` (`draft` / `conducted`), `contractor_id`, `currency`, `total`, `comment`, `created_by`, `created_at`, `updated_at`; порядок `id DESC` |
| `GET /documents/{id}` | то же плюс `lines`: `id`, `item_id`, `store_from`, `store_to`, `amount`, `purchasing_price`, `barcodes` |
| `GET /contractors`, `GET /contractors/{id}` | поля поставщика как в таблице `contractors` |

### Запись — `stock.write`

- `POST /documents` — черновик:
  ```json
  {"type":"A","xml_id":"WMS-1042","number":"WMS-1042","date":"2026-10-30","contractor_id":5,
   "currency":"RUB","comment":"","lines":[{"item_id":38391,"store_to":1,"amount":10,
   "purchasing_price":100,"barcodes":[]}]}
  ```
  - товар строки — `item_id` или `item_xml_id` (ровно одно; не найден — 422 с текстом
    «Не найден товар с внешним кодом X»);
  - автор и ответственный — пользователь ключа;
  - ответ 201 с документом (как `GET /documents/{id}`).
- `PUT /documents/{id}` — полная замена черновика (как сохранение формы); тип не меняется.
- `DELETE /documents/{id}` — удаление черновика, 204.
- `POST /contractors` — поставщик (`person_type` `I`/`C`, `person_name`, `company`, `inn`, `kpp`,
  `address`, `phone`, `email`, `post_index`), 201.

### Проведение — `stock.conduct`

- `POST /documents/{id}/conduct`, `POST /documents/{id}/cancel` — 200 с документом.

### Внешний код документа

Новая колонка `store_documents.xml_id TEXT` с уникальным индексом по непустым значениям.
Необязательна. Повторный `POST` с тем же `xml_id` — 409
`{"error":"conflict","message":"Документ с внешним кодом WMS-1042 уже есть","id":17}` без
изменений. В админке — поле «Внешний код» в форме документа и колонка в списке.

### Ошибки

| Код | Когда |
|---|---|
| 400 `bad_request` | неверный JSON, неизвестный тип документа, неверная дата или число, неверные параметры списка |
| 401, 403 | ключ и права (раздел 1) |
| 404 `not_found` | нет документа, поставщика, товара (lookup) |
| 409 `conflict` | правка или удаление проведённого документа; повторный `xml_id`; складской учёт выключен |
| 422 `rejected` | отказ правил склада: `{"error":"rejected","messages":[...]}` — тексты те же, что в админке (Битрикс) |

## 3. Устройство

- `src/apikeys.rs` — выпуск, отзыв, проверка ключа, extractor `ApiAccess`, функции
  `require(scope, permission)`.
- `src/stock_api/` — роутер `/api/stock/v1`, обработчики и JSON-типы; вызывают
  `stock::documents`, `stock::barcodes` и запросы чтения. Ошибки API — свой тип с JSON-ответом
  (общий `AppError::Forbidden` отдаёт HTML для админки).
- Админка — блок в карточке пользователя (`src/admin/users.rs`, шаблон формы пользователя).
- Миграция `0026_api_keys.sql`: `api_keys`, `store_documents.xml_id`.
- Полный ключ не пишется в логи: заголовок `Authorization` не логируется.

## Проверка

- **`sqlx::test`, ключи:** выпуск (секрет один раз, в базе хэш); 401 без заголовка, с неверным,
  отозванным, просроченным ключом, у неактивного пользователя; 403 без scope и без права; право
  отобрано у группы — ключ сразу 403; `last_used_at` не чаще раза в минуту.
- **Админка:** выпуск и отзыв по `users.manage`; ключи суперадминистратора недоступны обычному
  администратору; без `users.manage` блока нет.
- **Методы:** каждое чтение и запись, постраничность; создание по `item_xml_id`; повтор
  `xml_id` — 409 с `id`; правка и удаление проведённого — 409; отказ проведения — 422 со списком
  текстов; штрихкоды поштучного товара как в админке; закупочная цена в `lookup` только при
  `catalog.purchase_info`; автор документа — пользователь ключа; складской учёт выключен — 409.
- **Документация** `docs/api/stock.md`: выпуск ключа, заголовок, scope, каждый метод с `curl`,
  телом и ответом, ошибки; раздел «API склада» в README со ссылкой.
- **Сквозная проверка** и **регрессия** — по «Цели».
