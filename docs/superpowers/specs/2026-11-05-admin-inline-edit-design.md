# Админка, этап 3.3: правка в таблице — дизайн

Дата: 2026-11-05. Продолжение этапа 3 редизайна админки. Движок списков (этап 3.1:
`docs/superpowers/specs/2026-11-04-admin-lists-design.md`) и массовые действия (этап 3.2:
`docs/superpowers/specs/2026-11-05-admin-bulk-actions-design.md`) уже в `main`. Ветка
`feature/admin-inline-edit` от `main`.

## Цель и критерии успеха

Дать менять значения прямо в таблице списка записей коллекции, не открывая карточку.
Поведение сохранения совпадает с сохранением карточки: те же проверки прав, разбор и
проверка значений полей. Заказы и остальные списки админки не меняются.

Готово, когда:
- в списке записей коллекции у пользователя с правом записи редактируются название, код,
  сортировка, активность и одиночные поля типов строка, число, да/нет, дата, список;
- двойной клик по ячейке открывает редактор; `Enter`/уход фокуса сохраняют, `Esc` отменяет,
  `Tab` сохраняет и переходит к следующей редактируемой ячейке;
- «да/нет» переключается одним кликом;
- после сохранения список перерисовывается целиком, позиция страницы и текущая строка
  сохраняются, выбор строк сбрасывается;
- параллельная правка не затирается: при устаревшей версии записи сохранение отклоняется
  (409), список обновляется;
- пользователь без права записи не видит признаков редактируемости и получает 403 на
  прямой запрос;
- остальные списки, карточки и массовые действия работают как раньше.

Вне рамок: массовая правка значения поля у выбранных строк, редакторы для `text`, `file`,
`element` и любых множественных полей, правка заказов в таблице, выгрузка в CSV/Excel,
отмена и журнал правок, перевод остальных списков админки на движок.

## 1. Какие колонки редактируются

Только при `collection_level >= Write` для коллекции списка и праве записи на её родительскую
коллекцию (та же проверка, что у массовых действий и карточки).

| Колонка | Тип | Правила |
|---|---|---|
| `name` | строка | обрезается по краям; пустое — 422 «Укажите название» |
| `code` | строка | обрезается; пустой допускается и сохраняется пустым (в отличие от сохранения всей карточки, где генерируется из названия); непустой проверяется `collection::is_valid_slug`; занятый код — 422 «Код уже занят» |
| `sort` | целое | обрезается; не число — 422 «Сортировка: ожидается число» |
| `active` | да/нет | сохраняется булево |
| поле `string` | строка | по правилам `collection::fields::parse_value` |
| поле `number` | число | по правилам `parse_value` (запятая как разделитель) |
| поле `boolean` | да/нет | по правилам `parse_value` |
| поле `date` | дата | `ГГГГ-ММ-ДД`, по правилам `parse_value` |
| поле `list` | список | значение — id варианта этого поля; чужой вариант — 422 |

Не редактируются: `published_at` (дата-время: правка ячейкой потеряла бы часы и минуты),
`id`, `updated_at`, `section`, цены и остатки каталога, поля `text`, `file`, `element` и любые
множественные поля. Они по-прежнему правятся в карточке.

## 2. Спека списка

`src/admin/list/spec.rs`:

```rust
pub enum EditKind { Text, Number, Bool, Date, List }        // редактор в ячейке
pub enum EditTarget { Standard(StdField), Field(i64) }      // i64 — id поля коллекции
pub enum StdField { Name, Code, Sort, Active }

pub struct CellEdit {
    pub target: EditTarget,
    pub kind: EditKind,
    pub required: bool,
    pub options: Vec<EnumOption>,   // только для List
}
```

- `Column` получает `editable: Option<CellEdit>` и `edit_expr: Option<String>` — SQL-выражение
  сырого значения для редактора (не подпись из `expr`).
- `ListSpec` получает `version_expr: Option<String>` — SQL-выражение `updated_at`; `None` —
  список не редактируется.
- Построитель спеки коллекции (`collection.rs`) заполняет их только при праве записи и
  `parent_ok`. `field_entries` получает признак «можно править».
- Стандартные колонки: `name` → `ci.name`, `code` → `ci.code`, `sort` → `ci.sort`,
  `active` → `ci.active`. Поля коллекции — `(ci.field_values->>'{код}')` (у списка это id
  варианта, у даты строка, у числа текст). `version_expr` — `ci.updated_at`.
- Список заказов (`orders.rs`) не получает ни `editable`, ни `version_expr`.

`src/admin/list/sql.rs`: в выборку строк добавляются пары `'<код>__edit', <edit_expr>` для
редактируемых колонок и `'__version', <version_expr>`, когда версия задана.

`src/admin/list/render.rs`: `CellView` получает `edit: Option<&'static str>` (вид) и
`value: String` (сырое значение из `__edit`, `null` → пусто); `RowView` — `version: Option<String>`.
В `#list-spec` JSON добавляется `edit_columns`:
`[{code, kind, required, options: [{value, label}]}]`.

## 3. Запрос и сохранение

`POST /admin/lists/cell` (`src/admin/list/edit.rs`), форма:
`list_key`, `path`, `query`, `row`, `column`, `value`, `version` (`updated_at` строки).

1. `views::spec_for_key` — доступ к списку (403/404, как у видов и массовых действий).
2. `path` должен совпасть с `views::list_path(&list_key)` — иначе 422 «Неверный адрес списка».
3. Колонка ищется по коду; `editable` нет — 403 «Поле недоступно».
4. `collection_id` берётся из `list_key` (`collection:<id>`); для `EditTarget::Field` поле
   должно принадлежать этой коллекции, иначе 404. Попадание строки под текущий фильтр не
   проверяется: правка идёт по id и коллекции, а после ответа список перерисовывается и
   строка может из него выпасть.
5. Значение проверяется по разделу 1. Обязательное пустое — 422 с названием поля. Пустой
   `version` — 422 «Обновите список».
6. Атомарное сохранение (своя транзакция не нужна — один `UPDATE`):
   ```sql
   UPDATE collection_items
      SET name = $1, updated_at = now()                 -- стандартное поле
    WHERE id = $2 AND collection_id = $3
      AND updated_at = $4::timestamptz
   ```
   для поля коллекции:
   ```sql
   UPDATE collection_items
      SET field_values = jsonb_set(field_values, ARRAY[$1], $2::jsonb, true),
          updated_at = now()
    WHERE id = $3 AND collection_id = $4
      AND updated_at = $5::timestamptz
   ```
   `$2` — JSON-значение из разбора (`null`, строка, число, булево). Значения — только
   `push_bind`; в текст SQL — только выражения спеки.
7. `rows_affected = 1` — успех. `0` — запись проверяется отдельным `SELECT`: нет — 404
   «Запись не найдена», есть — 409 «Запись изменилась, список обновлён».
8. Нарушение уникальности кода (`23505`, `collection_items_code_key`) — 422 «Код уже занят».
   Прочие ошибки БД — 500 с `tracing::error!`.
9. Ответ — `views::rerender` для `path?query` и toast «Сохранено». 4xx список не подменяют
   (`HX-Reswap: none`, текст через `flash::toast`, как в `bulk.rs`).

## 4. Интерфейс

- Двойной клик по ячейке с `data-edit` открывает редактор: `input type="text"` для строки и
  числа, `input type="date"` для даты, `select` для списка (пустой пункт, если поле не
  обязательное).
- `Enter` и уход фокуса — сохранить; `Esc` — отменить без запроса; `Tab` — сохранить и
  перейти к следующей редактируемой ячейке.
- `да/нет` — один клик по ячейке переключает и сохраняет (без редактора).
- Первая колонка (`name`) остаётся ссылкой на карточку: одиночный клик открывает карточку,
  двойной — правит название. Одиночный переход задерживается примерно на 200 мс, чтобы
  распознать двойной клик.
- Во время запроса ячейка показывает «сохраняется», повторная отправка невозможна. После
  ответа список перерисовывается; позиция страницы и текущая строка сохраняются, выбор
  строк сбрасывается.
- На 409 — `list:refresh` и toast с текстом ошибки. На 422 — редактор остаётся открытым,
  значение можно исправить; toast с причиной.
- Правка не начинается при открытом поповере/диалоге и во время массового действия.
- Наведение на редактируемую ячейку показывает, что она правится (курсор/подчёркивание);
  у ячейки есть подсказка «Двойной клик — изменить».
- Без JS правки в таблице нет; карточка и остальные действия не меняются.
- На узком экране редактор не выходит за пределы ячейки/таблицы.

## 5. Ошибки

| Ситуация | Ответ |
|---|---|
| нет доступа к списку | 403/404 (как у видов) |
| колонка не редактируется у пользователя | 403 «Поле недоступно» |
| неверный `path`, значение не разобрано, обязательное пустое, чужой вариант списка, пустая версия | 422, toast с причиной |
| занятый код | 422 «Код уже занят» |
| запись удалена | 404 «Запись не найдена» |
| запись изменена параллельно | 409 «Запись изменилась, список обновлён» + перезапрос списка |
| ошибка БД | 500, лог |

4xx не подменяют список; уведомление — `flash::toast`.

## 6. Тесты

- **Юнит:** какие колонки получают `editable` (только разрешённые типы, только одиночные,
  только при праве записи); разбор значения каждого вида; обязательное пустое; чужой вариант
  списка; `published_at`/`id`/`updated_at` не редактируются.
- **Спека:** у списка записей `version_expr` задан, у списка заказов — нет.
- **С БД (маршрут):** правка `name`, `code`, `sort`, `active`; поля строки, числа, да/нет,
  даты, списка; обязательное пустое → 422; чужой вариант списка → 422; занятый код → 422;
  устаревшая версия → 409 и запись не изменилась; удалённая запись → 404; запись другой
  коллекции → 404; пользователь с `read` → 403; после правки ответ — `#list-body` с новым
  значением.
- **Шаблон:** у пишущего есть `data-edit`, `data-version` и `edit_columns`; у читающего их нет.
- **JS:** `node --check static/admin/list.js`.
- **Браузер (Chrome):** двойной клик, `Enter`/`Esc`/`Tab`, переключение «да/нет», правка
  списка, ошибка (обязательное/чужой вариант), 409 (две вкладки), сброс выбора, узкий экран.

## 7. Порядок внедрения

1. Спека: `CellEdit`/`EditKind`/`EditTarget`, `edit_expr`, `version_expr`, `__edit`/`__version`,
   разметка ячеек и `edit_columns`.
2. `src/admin/list/edit.rs`, маршрут `POST /admin/lists/cell`, сохранение и проверки.
3. `static/admin/list.js`, `_list_body.html`: редакторы, клавиши, 409.
4. Тесты, `README` («Интерфейс админки» → «Списки»), итоговая проверка.
