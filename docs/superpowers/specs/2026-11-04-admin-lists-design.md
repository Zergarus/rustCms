# Админка, этап 3.1: движок списков — дизайн

Дата: 2026-11-04. Продолжение редизайна админки (этап 1 — оболочка:
`docs/superpowers/specs/2026-10-28-admin-shell-design.md`; этап 2 — карточки:
`docs/superpowers/specs/2026-10-31-admin-cards-design.md`; оба в `main`). Стиль — Linear/Notion,
без отдельного фронтенд-проекта: MiniJinja, HTMX, чистый JS.

Интерактивный прототип интерфейса: https://claude.ai/artifact/Nh4rsvVH7JtEHbw4q8GJTB
(локально `.superpowers/tmp/list-demo.html`, вне git).

## Место в этапе 3

Этап 3 «Списки» разбит на три подпроекта, у каждого своя спека и план:

1. **Движок списков** (эта спека): описание списка, фильтры-чипы, сортировка, колонки,
   сохранённые виды, избранные виды в меню, дерево разделов, J/K.
2. Массовые действия: чекбоксы, «выбрать все по фильтру», действия над выбранным.
3. Правка в таблице.

Подпроекты 2 и 3 строятся на движке и здесь не проектируются.

## Цель и критерии успеха

Заменить самодельные списки записей коллекций и заказов общим движком, который подключает
следующий список одним описанием. CMS — универсальный шаблон (аналог Битрикса), поэтому список
коллекции строится из её полей во время работы, а не под конкретный проект.

Готово, когда:
- списки записей коллекций и заказов работают на движке; старая форма фильтра заказов и таблица
  подразделов удалены;
- фильтры задаются чипами, по стандартным полям записи, полям коллекции и каталожным данным
  (цены по типам, общий остаток, остатки по складам, «в наличии»);
- клик по заголовку сортирует, набор и порядок колонок настраиваются;
- всё состояние списка лежит в URL, кнопки «назад/вперёд» работают;
- виды сохраняются, бывают личными и общими, закрепляются в меню;
- у коллекций слева дерево разделов; раздел показывает записи вместе с подразделами, галочка
  «только этот раздел» сужает;
- J/K, Enter, Space, F, /, { } работают в обоих списках;
- остальные списки админки не изменились.

Вне рамок: остальные списки (справочники магазина, пользователи, скидки и т. д.) — переводятся
позже по одному описанию; массовые действия; правка в ячейке; полнотекстовый поиск (подпроект
«SEO и поиск»).

## 1. Описание списка (`ListSpec`)

Новый модуль `src/admin/list/`. Спека — данные без SQL-запросов к базе и без HTTP:

- `key` — ключ списка: `orders`, `collection:<id>`;
- `columns` — колонки: `code`, `title`, SQL-выражение, тип, `sortable`, `default` (видна по
  умолчанию), `align`;
- `filters` — фильтры: `code`, `label`, группа (для списка «+ Фильтр»), тип, SQL-выражение,
  источник вариантов для перечисления;
- `from` — базовый `FROM … WHERE` (с проверкой прав, например `collection_id = $1`);
- `joins` — подключаемые источники (см. ниже), каждый со своим кодом;
- `default_sort`;
- `can_share(&Access) -> bool` — может ли пользователь делать общие виды этого списка.

Типы: `text`, `number`, `money`, `date`, `bool`, `enum`, `link` (привязка к записи по ID),
`file` (только колонка).

Операторы по типам (код в URL → смысл):

| Тип | Операторы |
|---|---|
| text | `has` содержит (ILIKE), `eq` равно, `empty`, `notempty` |
| number, money | `eq`, `ne`, `gt`, `lt`, `between:a,b`, `empty` |
| date | `today`, `d7`, `d30`, `range:YYYY-MM-DD,YYYY-MM-DD` (любой край может быть пустым) |
| enum | `in:a,b`, `nin:a,b` |
| bool | `eq:Y`, `eq:N` |
| link | `eq:<id>`, `empty`, `notempty` |

### Спека заказов

Статическая. Колонки: номер, дата, покупатель, статус, сумма, оплата, доставка, отменён,
оплачен. Фильтры повторяют нынешнюю форму (номер, статус, период, покупатель, оплачен, отменён)
плюс сумма, оплата, доставка. `can_share` — `orders.manage`.

### Спека коллекции

Собирается по `collections` и `collection_fields` при каждом запросе.

- **Стандартные поля записи:** ID, название, код, активность, сортировка, раздел (только
  колонка — путь раздела), дата публикации, дата изменения.
- **Поля коллекции** (`collection_fields`, значения в `collection_items.field_values` JSONB по
  коду поля): `string`, `text` → text; `number` → number; `boolean` → bool; `date` → date;
  `list` → enum с вариантами из `collection_field_options`; `element` → link; `file` → только
  колонка. Одиночное значение читается как `field_values->>'code'` (с приведением типа для
  чисел и дат). Значения полей-списков и привязок — числовые id (варианта или записи), поэтому
  «любой из» — `OR` проверок вхождения `field_values @> $n` с JSON `{"code": id}` (одиночное) или
  `{"code": [id]}` (множественное); так работает GIN-индекс `collection_items_values_idx`.
  Сортировка по множественному полю недоступна.
- **Каталог** (если коллекция — каталог): колонка и фильтр цены на каждый тип цены
  (`catalog_price_types`; базовая строка цены — `quantity_from IS NULL`), общий остаток
  (`catalog_products.quantity`), остаток по каждому активному складу (`catalog_store_amounts`),
  фильтр «в наличии» (общий остаток > 0).

Каталожные источники — подключаемые: `LEFT JOIN` нужного типа цены или склада добавляется в
запрос, только если его колонка видна или по нему есть фильтр или сортировка.

`can_share` — доступ на запись в коллекцию или `collections.manage`.

## 2. Состояние в URL

```
?f.status=in:N,P&f.price_1=gt:1000&f.name=has:кед
 &sort=-updated_at&cols=id,name,price_1,qty&page=2&per=50
 &section=15&only=1        ← только у коллекций; section=none — «без раздела»
```

- Один параметр `f.<code>` на фильтр; повтор кода — последнее значение.
- `sort=<code>` или `-<code>`; одна колонка сортировки.
- `cols` — видимые колонки по порядку; колонка «Название» (у заказов «№») обязательна.
- `per` — 20, 50 или 100.
- Значения нормализуются (`state.rs`): неизвестный код, неизвестный оператор, неразбираемое
  значение, лишний параметр — отбрасываются молча. Если URL изменился при нормализации, ответ
  несёт `HX-Replace-Url` с нормализованным адресом (для полной страницы — 302 на него).
- `page` за последней страницей сдвигается на последнюю.
- В SQL попадают только выражения из спеки; значения — только через `push_bind`.

## 3. Виды

```sql
CREATE TABLE admin_views (
    id         BIGSERIAL PRIMARY KEY,
    list_key   TEXT NOT NULL,
    owner_id   BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name       TEXT NOT NULL,
    query      TEXT NOT NULL,          -- нормализованная строка запроса без page
    shared     BOOLEAN NOT NULL DEFAULT FALSE,
    sort       INT NOT NULL DEFAULT 500,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX admin_views_list_idx ON admin_views (list_key);

CREATE TABLE admin_view_pins (
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    view_id BIGINT NOT NULL REFERENCES admin_views(id) ON DELETE CASCADE,
    sort    INT NOT NULL DEFAULT 500,
    PRIMARY KEY (user_id, view_id)
);
```

- Вид «Все» — системный, не хранится: спека без фильтров с колонками и сортировкой по умолчанию.
- Строка видов: «Все», затем общие, затем личные текущего пользователя.
- Состояние отличается от открытого вида → «Вид изменён · Сохранить · Сохранить как… ·
  Сбросить». «Сохранить» доступно для своего вида и для общего при `can_share`.
- «Сохранить как…» — название и галочка «Общий» (только при `can_share`).
- Меню вида «⋯»: переименовать, сделать общим/личным (при `can_share`), удалить
  (подтверждение в поповере).
- Закрепить (звёздочка) можно любой видимый вид. Закреплённые виды выводятся в левом меню под
  своим разделом (под коллекцией или под «Заказы»), клик открывает список с видом.
- Удалённая коллекция: её виды удаляются вместе с ней (по `list_key`, в коде удаления
  коллекции).

### Последнее состояние

`users.admin_prefs.lists.<key>` = `{cols, sort, per, tree_collapsed}`. Заход в список без
параметров восстанавливает колонки, сортировку и размер страницы; фильтры не восстанавливаются.
Пишется отдельным `UPDATE` только при изменении.

## 4. Интерфейс

Сверху вниз (см. прототип): хлебные крошки; заголовок с числом записей, «Колонки», «Добавить
запись»; строка видов; строка чипов; таблица; страницы.

- **Чипы.** «+ Фильтр» (клавиша F) — поповер со списком фильтров спеки, поиском и группами
  («Запись», «Поля коллекции», «Каталог»). Выбор → поповер оператора и значения: перечисление —
  чекбоксы с поиском, дата — быстрые варианты и период, число — поле, да/нет — две кнопки
  (применяется сразу). Готовый фильтр — чип «Подпись оператор значение ✕»; клик по чипу снова
  открывает поповер; ✕ убирает. «Сбросить всё» — при наличии фильтров. Каждое изменение —
  `hx-get` нового URL с `hx-push-url`.
- **Раздел** — особый чип «Раздел: Обувь ✕» (подсвечен); ставится кликом в дереве.
- **Колонки** — поповер: галочки и перетаскивание порядка, «По умолчанию».
- **Сортировка** — клик по заголовку: по возрастанию → по убыванию → по умолчанию.
- **Страницы** — ‹ 1 … 4 5 6 … 26 ›, выбор 20/50/100. `COUNT` ограничен 10 001: при
  превышении — «10 000+», последней страницы в навигации нет.
- **Дерево разделов** (только коллекции) — левая колонка, сворачивается (состояние в
  `admin_prefs`). Пункты «Вся коллекция», разделы с числом записей (вместе с подразделами),
  «Без раздела», «Добавить раздел». Ветки раскрываются лениво. Клик по разделу ставит чип
  «Раздел» и снимает «только этот раздел». Меню «⋯» узла: изменить раздел, добавить подраздел,
  добавить запись в раздел. Галочка «только этот раздел» видна, если у раздела есть подразделы.
  По умолчанию — записи раздела вместе с подразделами. На узком экране дерево — выезжающая
  панель.
- **Клавиши** (через `data-hotkey` оболочки; не работают при открытом поповере и в полях ввода):
  J/K — строка вниз/вверх с прокруткой; Enter — открыть карточку; Space — быстрый просмотр
  (заказы и товары каталога; J/K в открытой панели листают соседние записи); F — «+ Фильтр»;
  / — фильтр «Название содержит»; { } (Shift+[ и Shift+]) — страницы ([ ] уже листают вкладки
  оболочки).
- Пустой результат: «Ничего не найдено. Измените фильтры или сбросьте их».

## 5. Устройство на сервере

Модули `src/admin/list/`:

- `spec.rs` — типы спеки, построители спек заказов и коллекции.
- `state.rs` — `ListState`: разбор и запись нормализованной строки запроса. Чистые функции.
- `sql.rs` — сборка `SELECT` (выбранные колонки, нужные `joins`, `WHERE`, `ORDER BY`,
  `LIMIT/OFFSET`) и `COUNT` с `LIMIT 10001`.
- `views.rs` — CRUD видов, закрепления, проверки прав.
- `render.rs` — контекст шаблона; выбор ответа: фрагмент (`HX-Request` + `HX-Target`, правило
  из `src/admin/mod.rs`) → только `#list-body` (чипы, таблица, страницы), иначе полная страница.
- Шаблоны `templates/admin/_list.html`, `templates/admin/_tree.html`; строки таблицы — общие
  ячейки по типу колонки (`_list_cell` макрос), строки с быстрым просмотром сохраняют
  `data-peek`. Набор колонок у каждого пользователя свой, поэтому панель быстрого просмотра больше
  не присылает строку out-of-band: после изменения в панели она сообщает `list:refresh`, и
  `#list-body` перезапрашивает текущий адрес.
- `static/admin/list.js` — поповеры фильтров и колонок, перетаскивание колонок, клавиши. Описание
  фильтров и варианты перечислений — JSON в `<script type="application/json">` на странице.
  Применение — `htmx.ajax('GET', url, {target: '#list-body', pushUrl: true})`.

Маршруты:

- `GET /admin/collections/{id}/items`, `GET /admin/shop/orders` — прежние адреса на движке;
  `?view=<id>` открывает вид (подставляет его `query`, адрес заменяется на параметры вида).
- `GET /admin/collections/{id}/tree?parent=<id>` — ветка дерева.
- `POST /admin/views` — создать (`list_key`, `name`, `query`, `shared`).
- `POST /admin/views/{id}` — изменить `query`, `name` или `shared`.
- `POST /admin/views/{id}/delete`, `POST /admin/views/{id}/pin` (переключатель).

Права:

- Список — прежние проверки: доступ на чтение коллекции, для заказов `require_orders`.
- Виды: свой — меняет и удаляет владелец; общий — создаёт, меняет, удаляет пользователь с
  `can_share` и доступом к списку. Чужой личный вид для постороннего — 404. Запрос вида
  проверяется заново при каждом открытии (нормализация по текущей спеке).

## 6. Ошибки

- Неверные параметры URL — молча отбрасываются, адрес нормализуется (раздел 2).
- Вид ссылается на удалённое поле, тип цены или склад — открывается без этого фильтра или
  колонки, уведомление «Фильтр по полю “X” больше недоступен»; вид не переписывается, пока
  пользователь его не сохранит.
- Раздел из URL удалён или из другой коллекции — чип раздела отбрасывается.
- Ошибка базы во фрагменте — общее уведомление об ошибке, таблица остаётся прежней (HTMX не
  подменяет цель при ответе с ошибкой); для полной страницы — обычная страница ошибки.
- Ошибки форм видов (пустое название, нет права на общий вид) — уведомление, поповер остаётся
  открытым.

## 7. Тесты

По схеме проекта: модульные тесты и `test_support` с тестовой базой.

- **`state.rs`:** разбор → запись → разбор без потерь; отбрасывание мусора; все операторы по
  всем типам; обязательная колонка; ограничения `per`.
- **`sql.rs`:** снимки SQL для набора состояний; ни одна строка из URL не попадает в текст
  SQL; `joins` подключаются только при использовании.
- **С базой:** фильтры по полям коллекции (одиночным и множественным, enum, number, date,
  link), по цене типа, общему остатку, складу, «в наличии»; раздел с подразделами и «только
  этот раздел», «без раздела»; сортировка; страницы и ограничение `COUNT`; нынешние фильтры
  заказов дают те же результаты, что старая форма.
- **Виды:** создание, изменение, удаление; `shared` без права — отказ; чужой личный вид — 404;
  закрепление и вывод в меню; вид с удалённым полем открывается с уведомлением; удаление
  коллекции удаляет её виды.
- **Ответы:** фрагмент или полная страница по заголовкам; `HX-Replace-Url` при нормализации.
- **Smoke:** списки товаров и заказов у пользователя с правом только на чтение.
- **Браузер:** проверка через Chrome на dev-сервере: дерево, чипы, виды, колонки, клавиши.

## 8. Порядок внедрения

1. Ядро: `spec`, `state`, `sql` с тестами.
2. Заказы на движке; удаление старой формы фильтра.
3. Записи коллекций: спека из полей, каталожные источники, дерево; удаление таблицы подразделов.
4. Виды: миграция, CRUD, строка видов, закрепление в меню.
5. `list.js`: поповеры, колонки, клавиши.
