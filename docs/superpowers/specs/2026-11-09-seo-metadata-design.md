# SEO: метаданные CMS, первый этап

Пользователь разрешил после аудита начинать реализацию по приоритету. Технические решения ниже приняты исполнителем.

## Аудит и очередь

- SEO: в src, migrations, templates нет хранения title/description/H1 и наследования. Есть шаблоны URL в collections, breadcrumbs и nav/legacy-redirect в src/bxapi/nav.rs; их не дублируем.
- Цены: src/catalog/mod.rs хранит quantity_from/to, но main_price выбирает базовую/первую цену; следующий этап — выбор по количеству и группам во всех каналах.
- Оплата: src/bxapi/order.rs возвращает paymentUrl:null; справочники и учёт оплат есть, интеграция онлайн-провайдера — отдельный этап.
- Склад: документы, резервы, возвраты, партии, себестоимость и API уже есть. Не объявлять их отсутствующими; отдельно нужны инвентаризация и удобные отчёты/печать.
- Формы: src/bxapi/forms.rs уже принимает обращения. Полный маркетинговый модуль и управление обращениями требуют отдельной детализации.
- Импорт: src/import.rs переносит контент и справочники, но не SEO. История заказов и SEO требуют отдельных проверяемых этапов миграции.
- Доставка: src/sale/form.rs уже выдаёт службы и склады самовывоза, есть фильтры/хуки проекта. Условия по географии/корзине и интеграции перевозчиков не следует путать с отсутствием доставки вообще.
- Каталог: src/catalog/mod.rs и миграции дают SKU/цены/остатки; единицы/коэффициенты/НДС требуют следующей отдельной доработки. Сортировка «цена от предложений» также не закрыта базовым выбором цены.
- Подарки: src/bxapi/gifts.rs уже рассчитывает предложения подарков. Следующий шаг — автоматическое добавление/удаление в корзине, а не новый движок скидок.
- Отчёты: расчёт себестоимости и маржи есть в src/stock/cost.rs; полноценные отчёты, печать и экспорт таблиц остаются отдельной работой. XML-экспорт заказов в 1С уже реализован, его не смешиваем с CSV/Excel.
- Поиск: по решению пользователя отдельный этап не планируется.

Порядок после SEO: покупательские цены → онлайн-оплата → каталог (единицы/НДС/цена от) и доставка по фактическим требованиям → миграция истории → отчёты/инвентаризация → маркетинг/формы/автоподарки. Наличие hooks или схемы БД не считается завершённой пользовательской функцией. Это аудит названных функциональных блоков, не аудит безопасности или всех возможных функций Битрикса.

## Подходы

1. Произвольные свойства контента: легко добавить, но нет единого наследования и редактора.
2. Отдельный SEO-модуль с таблицей настроек и API: выбран, сохраняет существующие контракты и не раздувает модели контента.
3. Полная эмуляция шаблонизатора Битрикса: слишком большой первый этап; импорт потребует явной поддержки/диагностики выражений.

## Объём первого этапа

Title, description, H1 на коллекции, разделе и записи. Значения раздела применяются также к потомкам и записям. Наследование каждого поля независимо: коллекция → корневой раздел → дочерний → запись. Пустое поле означает наследовать. Без шаблона title/H1 = имя текущего объекта, description = пустая строка.

Простые безопасные подстановки `{name}`, `{code}`, `{collection}`, `{section}`. Контекст всегда текущего объекта, section — его раздел (для самого раздела — он сам). Значения не исполняются и не раскрываются рекурсивно. Неизвестные/незакрытые переменные отклоняются при сохранении. Максимум 2000 символов на шаблон.

Отдельная HTML-форма `/admin/seo/{kind}/{id}` (kind collections/sections/items), ссылки из существующих карточек, сохранение/предпросмотр итоговых значений. Права: настройки коллекции требуют collections.manage; записи/разделы — Write своей коллекции. Применяется существующая защита Origin.

GET `/api/v1/seo/{kind}/{id}` возвращает `{title, description, h1}` для api_enabled коллекции и активного опубликованного контента с активными предками. Закрытые/несуществующие объекты — 404. API читает актуальные настройки, без кеша; прежние bxapi-ответы не изменяются. Фронтенд должен явно подключить новый API и экранировать текст при рендере HTML.

Таблица с внешними ключами на коллекцию/раздел/запись и ON DELETE CASCADE; ровно один владелец. Все три поля сохраняются атомарно.

## Следующие SEO-этапы

Импорт шаблонов/переопределений из Битрикса, canonical/robots, sitemap, произвольные перенаправления и подключение Nuxt. Первый этап не объявляется полной SEO-готовностью сайта. Новые зависимости не нужны.
