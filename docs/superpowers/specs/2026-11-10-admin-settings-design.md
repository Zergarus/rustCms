# Настройки сайта и почтовые шаблоны в админке

Сейчас то, что контент-менеджер меняет сам, живёт только в БД: реквизиты сайта
(`options`, модуль `main`) и почтовые шаблоны (`mail_templates`, переносятся
импортом). Без страниц в админке любая правка — это SQL. Закрываем это, чтобы
CMS была продуктом, а не набором таблиц.

## Что делаем

### 1. «Настройки сайта» — `/admin/settings`

Форма поверх `options` (модуль `main`):

- `site_name` — название сайта (`#SITE_NAME#` в письмах);
- `server_name` — домен (`#SERVER_NAME#`);
- `email_from` — отправитель по умолчанию (`#DEFAULT_EMAIL_FROM#`).

Пустые значения допустимы: почта подставит то, что есть, как сейчас. Права —
суперадминистратор (как настройки модулей в Битриксе).

### 1a. SMTP для писем

В той же форме — блок SMTP: `smtp_host`, `smtp_port`, `smtp_user`,
`smtp_password`, `smtp_secure` (`auto` / `none` / `starttls` / `tls`), поверх
`options` модуля `mail`. Приоритет источников: `MAIL_SMTP_URL` из окружения
(деплой) → настройки в БД → сохранение писем в `.eml` (как сейчас, если SMTP не
настроен ни там, ни там).

- Пароль в БД, как в Битриксе; в форму он не отдаётся — пустое поле означает
  «не менять». Шифрование пароля — в техдолг.
- `auto`: порт 465 — неявный TLS, остальные — STARTTLS.
- Порт проверяется диапазоном 1–65535, тип шифрования — из четырёх значений.

### 2. «Почтовые шаблоны» — `/admin/mail`

Список `mail_templates` и форма правки: `event_name`, `active`, `email_from`,
`email_to`, `bcc`, `subject`, `body`, `body_type` (`text` / `html`).
Создание и удаление шаблона. Права — суперадминистратор.

Проверки: `event_name` — заглавные латиница, цифры и `_`; `subject` и `body` не
пустые; `body_type` только из двух значений. В форме подсказка про подстановки
`#ПОЛЕ#` и поля по умолчанию.

## Решения

- Новая таблица не нужна: `options` и `mail_templates` уже есть.
- Отдельного права `settings.manage` не вводим — только супер; гранулярное
  право уедет в техдолг, если понадобится.
- Валидация плейсхолдеров (`#AUTHOR#` vs `#AUTHOR`) не делается: шаблоны
  приходят из Битрикса с десятками макросов, ложные срабатывания дороже пользы.
- Редактирование HTML-шаблона — обычная textarea без предпросмотра (превью
  письма — отдельная задача).

## Файлы

- `src/admin/settings.rs`, `src/admin/mail.rs` — обработчики.
- `templates/admin/settings.html`, `templates/admin/mail_list.html`,
  `templates/admin/mail_form.html`.
- `src/admin/mod.rs` — маршруты; `src/admin/nav.rs` — пункты меню.
- `src/settings.rs` — чтение/запись `options` модуля `main`.
- `src/mail_templates.rs` — CRUD шаблонов.
- `src/settings_tests.rs` — тесты.
