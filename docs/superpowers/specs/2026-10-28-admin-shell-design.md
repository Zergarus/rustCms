# Админка: новая оболочка (этап 1 из 3)

## Цель

Админка CMS должна выглядеть и работать как современный инструмент в духе Linear и Notion: меню, где CMS на первом месте, вкладки открытых записей, командная палитра, управление с клавиатуры, карточки на вкладках вместо длинной ленты блоков.

CMS — универсальный шаблон, поэтому магазин в меню — модуль под одной кнопкой, а не основа админки.

Пользователи: контент-менеджеры, менеджеры заказов, администратор сайта.

## Решения

- **Технологии.** Сервер собирает страницы из шаблонов MiniJinja, HTMX подгружает фрагменты, остальное делает один свой JS-файл без сборки и npm. Отдельного фронтенд-проекта нет. Права, проверки и тесты остаются на сервере.
- **Макет-ориентир:** https://claude.ai/artifact/RdMwLotX48HM14bsMmqAbA (тёмная тема, индиго-акцент).
- **Этапы:**
  1. **Оболочка** — этот документ.
  2. **Карточки:** товар, пользователь, коллекция и скидка на вкладках, быстрый просмотр в боковой панели.
  3. **Списки:** сохранённые виды, фильтры-чипы, правка в таблице, массовые действия, J/K.
- **Ветка.** `feature/admin-shell` создана от `feature/stores`, потому что меню магазина включает раздел «Склад». Сливается после `feature/stores`.

## 1. Меню и модули

### Реестр разделов

Меню строится на сервере, в новом модуле `src/admin/nav.rs`, а не перечисляется в `base.html`. Из этого же реестра берут разделы палитра и подписи вкладок.

Каждый пункт реестра содержит:
- код и название;
- адрес;
- группу;
- модуль (`None` или `shop`);
- условие видимости: функцию от `Access` и настроек.

### Основное меню

1. **Рабочий стол** (`/admin`).
2. **Контент.**
   - Коллекции, которые пользователь может видеть, в порядке `sort`, у каждой счётчик записей.
   - Если коллекций больше 8, показываются первые 8 и пункт «Ещё…», который ведёт на `/admin/collections`.
   - Внизу пункт «Все коллекции».
3. **Модули.** Кнопка «Магазин» видна при трёх условиях: модуль включён, у пользователя есть `shop.manage` или `orders.manage`, есть хотя бы один видимый пункт магазина. Рядом со значком — число неотменённых заказов в начальном статусе `N` (`sale::INITIAL_STATUS`); если у пользователя нет `orders.manage`, числа нет.
4. **Система.** Пользователи (`users.manage`), Группы и права (администратор), Модули (администратор).

### Меню магазина

Показывается вместо основного на адресах `/admin/shop/*`, `/admin/discounts*` и `/admin/exchange*`.

- **Шапка:** «‹ Все разделы», затем заголовок «Магазин».
- **Заказы** (`orders.manage`).
- **Товары:** коллекции с `is_catalog`. Если такая коллекция одна, пункт ведёт прямо в неё, иначе — на список таких коллекций.
- **Каталог:** Типы цен, Правила округления.
- **Склад:** Склады, а при включённом складском учёте ещё Остатки и Документы; Поставщики. Это то же условие, что в нынешнем `shop/_nav.html`.
- **Маркетинг:** Скидки, Купоны, Накопительные скидки. Права — `discounts.manage`, адреса прежние (`/admin/discounts*`).
- **Настройки магазина:** Статусы, Доставки, Платёжные системы, Типы плательщика, Валюты, Курсы валют, Настройки каталога, Корзины, Обмен с 1С. Обмен с 1С требует `exchange.1c` или `exchange.1c.sale`.

Права остальных пунктов такие же, как у вкладок в нынешнем `shop/_nav.html`. Группа, в которой не видно ни одного пункта, скрывается.

### Модули

- **Настройка.** Новая запись в `options`: `module = 'admin'`, `name = 'module_shop'`, значение `Y` или `N`. Если записи нет, модуль считается включённым.
- **Страница** `/admin/modules` (только администратор): список модулей с переключателем; пока там один модуль, «Магазин».
- **Выключенный магазин:**
  - убирается из меню, палитры и рабочего стола;
  - адреса меню магазина отвечают 404 со страницей «Модуль „Магазин“ выключен» и ссылкой на `/admin/modules` для администратора.
- **Чего выключатель не касается:** API сайта, `bxapi`, обмена с 1С по `/bitrix/admin/1c_exchange.php`. Он отключает только интерфейс.

### Свёрнутые группы

Группы меню сворачиваются через `<details>`. Состояние хранится в `localStorage` браузера, и любая ошибка доступа к хранилищу просто игнорируется.

## 2. Вкладки открытых записей, палитра, горячие клавиши

### Вкладки открытых записей

Таблица (миграция `0024_admin_shell.sql`):

```
admin_tabs(
  id BIGSERIAL PK,
  user_id → users ON DELETE CASCADE,
  key TEXT,            -- адрес записи без вкладки карточки и без параметров
  url TEXT,            -- последний открытый адрес (вкладка карточки, фильтры)
  title TEXT,
  kind TEXT,           -- content | shop | system
  opened_at TIMESTAMPTZ,
  UNIQUE(user_id, key)
)
```

- **Ключ** — путь без параметров. У карточек с вкладками это адрес самой записи: `/admin/shop/orders/1042/shipment` → `/admin/shop/orders/1042`. Список вкладок карточек задаёт реестр в `nav.rs`.
- **Что не открывает вкладку:**
  - страница входа;
  - формы создания (`/new`);
  - ответы с ошибкой;
  - страницы, где в `base.html` задан `{% set no_tab = true %}`.
- **Открытие.** После каждой загрузки страницы и каждого перехода через `hx-boost` JS отправляет `POST /admin/tabs` с полями `url` и `title`. Сервер:
  - нормализует ключ;
  - создаёт вкладку или обновляет у существующей `url`, `title` и `opened_at`;
  - если вкладок больше 10, удаляет самую старую по `opened_at`, но не текущую;
  - возвращает HTML строки вкладок.
- **Закрытие.** `POST /admin/tabs/{id}/close` отвечает HTML строки. Если закрыта активная вкладка, сервер дополнительно отдаёт `HX-Location` с адресом соседней (правой, а если её нет — левой). После последней — `/admin`.
- **Тип вкладки** (`kind`) берётся из реестра: контент, магазин или система. Он определяет цвет точки.
- **Удалённая запись.** Если адрес вкладки отвечает 404, вкладка удаляется при следующем открытии записи. При отрисовке строки ничего не проверяется.
- **Права.** Вкладки видит и закрывает только их владелец. Чужой `id` даёт 404.
- **Отключение.** Опция пользователя «Показывать вкладки открытых записей», по умолчанию включена. Хранится в новой колонке `users.admin_prefs JSONB NOT NULL DEFAULT '{}'`, ключ `tabs`.

### Командная палитра

- **Как открыть:** Ctrl+K (на Mac — Cmd+K) или кнопкой «Найти или выполнить…» в меню. Окно `role="dialog"`, фокус в поле ввода.
- **Как ищет.** `GET /admin/palette?q=` отдаёт HTML-фрагмент; запрос уходит через 150 мс после ввода. Поиск по подстроке без учёта регистра (`ILIKE`, спецсимволы экранируются).
- **Пустой запрос** показывает до 5 последних вкладок и действия.
- **Группы результатов**, до 5 в каждой, в таком порядке:
  1. **Разделы** — из реестра, только видимые пользователю.
  2. **Действия** — из реестра. У каждого пункта есть необязательное действие «создать»: «Новый заказ», «Новый документ прихода», «Добавить запись в „<коллекция>“» для коллекций с правом записи.
  3. **Заказы** — при `orders.manage`: номер (точный или по префиксу), имя, телефон или почта покупателя.
  4. **Записи коллекций** — по названию, только в коллекциях, доступных пользователю для чтения.
  5. **Пользователи** — при `users.manage`: логин, имя, почта.
- **Выключенный магазин:** разделы, действия и заказы магазина не показываются.
- **Управление:** ↑ и ↓ — выбор, Enter — открыть, Esc — закрыть, клик вне окна — закрыть.

### Горячие клавиши

Не срабатывают, пока фокус в `input`, `textarea`, `select` или `[contenteditable]`, и пока открыта палитра (кроме Esc).

- **`G`, затем буква в течение 1 с** — переход: `G D` рабочий стол, `G O` заказы, `G C` коллекции, `G U` пользователи. Если раздел пользователю недоступен, клавиша ничего не делает.
- **`C`** — кнопка с `data-hotkey="c"` на текущей странице.
- **`/`** — поле с `data-hotkey="/"`.
- **`?`** — окно со списком клавиш.
- **Ctrl+S (на Mac — Cmd+S)** — отправить форму, у которой видна панель сохранения.

Клавиши задаются атрибутом `data-hotkey` на элементе, поэтому новым разделам не нужно править JS.

## 3. Макет страницы, компоненты, тема

### Файлы

- `templates/admin/base.html` — оболочка: строка вкладок, меню, основная область.
- `templates/admin/_ui.html` — макросы:
  - `page_head(crumbs, actions)`;
  - `tabs(items, active)`;
  - `aside()` (блок `call`);
  - `prop(label)`;
  - `card(title)`;
  - `empty(text, action)`.
- `static/admin/admin.css` — переписывается на CSS-переменные.
- `static/admin/admin.js` — палитра, клавиши, вкладки, панель сохранения, уведомления. Цель — не больше 600 строк.
- `static/admin/fonts/Inter-*.woff2` — шрифт хранится локально.

### Компоненты

- **Вкладки карточки.** Каждая — `<a href>` с `hx-get`, `hx-target` на область вкладки, `hx-push-url="true"` и `aria-current` у активной. Без JS работают как обычные ссылки. Вкладка, где форма вернулась с ошибкой, помечается точкой с текстом для экранного диктора.
- **Панель сохранения.** Форма с атрибутом `data-dirty-guard`. После первого изменения поля внизу появляется панель «Есть несохранённые изменения · Отменить · Сохранить». «Отменить» вызывает `form.reset()`. При уходе со страницы с несохранёнными правками срабатывает `beforeunload`, а для переходов через HTMX — подтверждение в событии `htmx:beforeRequest`.

### Уведомления

Системный `alert()` больше не используется.

- **После перехода.** Обработчик ставит одноразовую cookie `admin_flash` (`HttpOnly`, `SameSite=Lax`, `Path=/admin`, без шифрования, только текст и тип). `base.html` показывает уведомление и сбрасывает cookie в том же ответе.
- **После HTMX.** Заголовок `HX-Trigger: {"toast": {"text": "…", "kind": "ok|error"}}`.
- **Ошибки 4xx и 5xx у HTMX-запросов** — красное уведомление с первыми 300 символами ответа.
- **Время показа:** уведомления исчезают через 4 с, ошибки — по крестику. Контейнер — `aria-live="polite"`.

### Тема

- **Варианты.** Тёмная и светлая палитры в переменных. `data-theme` на `<html>`: `dark`, `light` или отсутствует (берётся системная, `prefers-color-scheme`).
- **Хранение.** Выбор хранится в `users.admin_prefs.theme`, переключатель — в меню профиля (аватар внизу меню).
- **Контраст.** Текст не ниже 4.5:1 в обеих темах. Фокус виден (`:focus-visible`, рамка 2 px акцентным цветом).

### Узкий экран

- **Меньше 900 px:** меню становится выезжающей панелью по кнопке ☰.
- **Строка вкладок** прокручивается по горизонтали.
- **Колонка справа** уходит под содержимое.
- **Таблицы** прокручиваются внутри своего блока.

### Существующие страницы

- **Совместимость.** Все шаблоны продолжают наследовать `base.html` через блоки `title` и `content` и работают без правки.
- **Подсветка пункта меню.** Переменные `section` и `tab`, которые шаблоны ставят сейчас, остаются ключами активного пункта.
- **`shop/_nav.html`** и его `include` удаляются.
- **Удобства в старом `base.html`** (`hx-boost`, обработка 403 через `htmx-config`) сохраняются.

## 4. Карточка заказа на вкладках

### Адреса вкладок

GET-маршруты в одном обработчике `orders::view` с параметром вкладки:

| Вкладка | GET | Содержимое |
|---|---|---|
| Обзор | `/admin/shop/orders/{id}` | Статус, оплата и отмена (их формы) строками «подпись — значение», покупатель кратко, состав только для чтения, комментарий покупателя |
| Состав и скидки | `/admin/shop/orders/{id}/items` | Форма состава, пересчёт скидок, применённые правила |
| Покупатель и свойства | `/admin/shop/orders/{id}/props` | Покупатель, форма свойств |
| Отгрузка и резервы | `/admin/shop/orders/{id}/shipment` | Форма отгрузки со складами позиций, резервы с кнопками |
| Документы и 1С | `/admin/shop/orders/{id}/files` | Файлы-документы, состояние выгрузки, ссылка на XML |
| История | `/admin/shop/orders/{id}/history` | История статусов |

- **Неизвестная вкладка** — 404.
- **POST-маршруты остаются прежними.**

### Колонка справа

На всех вкладках: итого, товары, скидка, доставка, статус, оплата и отгрузка.

При HTMX-запросе колонка приходит вместе с вкладкой как out-of-band фрагмент (`hx-swap-oob`), так что после правки состава итоги обновляются сразу.

### После POST

- **Успех:** переход 303 на вкладку, к которой относится действие:
  - status, paid, cancel → Обзор;
  - items, discounts → Состав;
  - props → Покупатель;
  - shipment, reserve, unreserve → Отгрузка;
  - files → Документы.

  Плюс уведомление: «Статус изменён», «Состав сохранён» и т. п.
- **Ошибка формы:** вкладка показывается с ошибкой (200), как сейчас карточка.

### Ответы

- **Обычный запрос** — страница целиком.
- **С `HX-Request` и `HX-Target` области вкладки** — только вкладка и колонка справа.

**Не меняется:** логика заказа, права, проверки и тексты ошибок.

## 5. Проверка

### Тесты (`cargo test`)

- **Меню:**
  - пункты по правам;
  - выключенный магазин;
  - складской учёт (Остатки и Документы);
  - пустая группа скрыта;
  - «Ещё…» при 9+ коллекциях.
- **Вкладки:**
  - открытие;
  - повторное открытие обновляет `url` и не плодит вкладки;
  - ключ без вкладки карточки;
  - лимит 10 без вытеснения текущей;
  - закрытие активной — `HX-Location` на соседнюю, последней — `/admin`;
  - чужая вкладка — 404;
  - `/new` и ошибки вкладку не открывают.
- **Палитра:**
  - разделы и заказы без прав не видны;
  - записи только из читаемых коллекций;
  - выключенный магазин скрыт;
  - экранирование `%` и `_`.
- **Модули:** выключенный магазин отвечает 404 со страницей модуля; API сайта отвечает как прежде.
- **Заказ:**
  - каждая вкладка отвечает 200 полной страницей и фрагментом;
  - неизвестная вкладка — 404;
  - POST ведёт 303 на свою вкладку;
  - ошибка формы рендерит вкладку.
- **Уведомление:** показывается один раз, cookie сбрасывается.
- **Тема:** `data-theme` из профиля.

### Регрессия

- Все текущие тесты зелёные.
- Ответы API сайта (`/api/v1`, `bxapi`) байт в байт как до этапа, на тех же 22 запросах, что в подпроекте «Склады».

### Ручная проверка в браузере (копия базы)

- Обе темы.
- Ширина 390 px.
- Палитра и клавиши.
- Сценарий заказа: правка состава → отгрузка → история, с проверкой вкладок открытых записей.
- Проверка контраста.

## Не входит

- Карточки товара, пользователя, коллекции и скидки на вкладках, боковая панель быстрого просмотра — этап 2.
- Сохранённые виды, избранные виды в меню, фильтры-чипы, правка в таблице, массовые действия, J/K — этап 3.
- Полнотекстовый поиск — подпроект «SEO и поиск». Палитра перейдёт на него.
- Изменения API сайта и `bxapi`, отключение кода магазина на сервере.
