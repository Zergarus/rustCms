# Торговые предложения (SKU) — дизайн

Дата: 2026-10-09. Подпроект 1 серии «до функционала Битрикса редакции „Бизнес“»
(переименование → **SKU** → обмен с 1С → скидки → остальные модули редакции).
Опирается на переименование (`2026-10-09-collections-rename-design.md`): словарь
«коллекция / запись / поле», миграция `0014`.

## Цель и критерии успеха

Паритет с торговыми предложениями Битрикса «Бизнес»: у товара есть предложения со своими
полями, ценами, остатками и весом; менеджер ведёт их в карточке товара и генерирует
сочетаниями; bxapi отдаёт их как Битрикс, умеет цену «от» и фильтр товаров по
предложениям; предложение кладётся в корзину и оформляется в заказ со свойствами.
Целевого проекта нет — проверка на демо-данных.

Готово, когда:

- админка: связь коллекций, вкладка предложений в карточке товара, генератор, признаки
  полей;
- bxapi: предложения через обычные ручки коллекции и `cml2Link`, `catalogType`, цена
  «от», фильтр `offers`; корзина, заказ, ЛК, письмо и админка заказа показывают свойства
  позиции;
- импорт SKU из Битрикса;
- сквозной сценарий на демо-данных и регрессия фронта трансопта пройдены, нагрузка
  измерена.

Не входит: единицы измерения, НДС и наценки (подпроект «Торговый каталог»); встраивание
предложений в ответ товара — фронт получает их отдельным запросом по `cml2Link`;
сортировка товаров по цене «от».

## Данные — миграция `0015_sku.sql`

- `collections.product_collection_id BIGINT UNIQUE REFERENCES collections ON DELETE SET
  NULL` — «коллекция предложений для коллекции N» (аналог `b_catalog_iblock`, у коллекции
  товаров не больше одной коллекции предложений); `collections.sku_field_id BIGINT
  REFERENCES collection_fields ON DELETE SET NULL` — системное поле `CML2_LINK`.
- `collection_items.product_id BIGINT REFERENCES collection_items ON DELETE CASCADE`,
  индекс по `product_id`. У записей коллекции предложений обязателен (проверка в коде при
  сохранении), у остальных — `NULL`.
- `catalog_products.type SMALLINT NOT NULL DEFAULT 1` — коды Битрикса: 1 простой, 3 с
  предложениями, 4 предложение, 6 с предложениями без предложений.
  `catalog_products.weight NUMERIC(18, 3) NOT NULL DEFAULT 0` — вес в граммах.
- `collection_fields.in_basket BOOLEAN NOT NULL DEFAULT FALSE` («показывать в корзине»,
  `IN_BASKET`), `collection_fields.offer_tree BOOLEAN NOT NULL DEFAULT FALSE` («поле
  выбора предложения», `OFFER_TREE`; допустимо для видов `list`, `element`, `string`).
- `cart_items.props JSONB NOT NULL DEFAULT '[]'` — свойства позиции `[{code, name,
  value}]` (аналог `b_sale_basket_props`); позиция заказа — та же строка, свойства
  остаются с ней.

### Тип и доступность — триггеры

Пересчёт товара-родителя `refresh_sku_product(product_id)`:

- есть хотя бы одно предложение → `type = 3`, `available` = доступно хоть одно активное
  предложение;
- предложений нет, а товар был типа 3 → `type = 6`, `available = false`;
- строка `catalog_products` родителя создаётся, если её нет.

Срабатывает: вставка, удаление, смена `product_id` или `active` у записи-предложения;
вставка, удаление, изменение `available`/`quantity`/флагов `catalog_products` предложения.
У предложения при сохранении `type = 4`. Рекурсии нет: у родителя `product_id` пуст.

Доступность самого предложения считается, как у простого товара (существующая логика
`available` / `quantity_trace` / `can_buy_zero`).

## Админка

- **Коллекция с каталогом**, блок «Торговые предложения»: «нет» / «использовать коллекцию
  X» / «создать новую». Новая: код `<код>_offers`, название «<название> — предложения»,
  каталог включён, системное поле `CML2_LINK` (вид `element`, привязка к коллекции
  товаров). `CML2_LINK` нельзя удалить или изменить, пока связь есть. Снять связь можно,
  если в коллекции предложений нет записей.
- **Карточка товара**, вкладка «Торговые предложения»: таблица (название, активность,
  поля выбора, базовая цена, сумма остатков), «изменить», «удалить», «Добавить
  предложение», «Сгенерировать». У товара типа 3/6 блок цен и остатков заменён пометкой
  «Цены и остатки задаются у предложений».
- **Форма предложения** — форма записи коллекции предложений, поле «Товар»
  (`CML2_LINK`) обязательно и предзаполнено; после сохранения — возврат в карточку товара.
- **Форма поля** — флажки «Показывать в корзине» и «Поле выбора предложения».
- **Вес** — в блоке каталога записи (граммы).
- **Права** — как у записей: вкладка и генератор требуют права записи на обе коллекции.

### Генератор

Страница из карточки товара:

- для каждого поля с `offer_tree`: список — галочки по вариантам; привязка — выбор
  записей; строка — значения через запятую;
- общие значения: активность, цена по каждому типу цен, остаток по каждому складу, вес;
- шаблон названия, по умолчанию `#PRODUCT_NAME# (#CODE1#, #CODE2#)` — коды полей выбора
  с выбранными значениями;
- создаются все сочетания, не больше 100 за запуск (больше — ошибка формы до записи);
  сочетание, уже существующее у товара (те же значения полей выбора), пропускается;
- `xml_id` нового предложения — UUID;
- итог: «Создано N, пропущено M (уже есть)», возврат на вкладку.

## bxapi

Как в Битриксе:

- коллекция предложений — обычная коллекция со своим API-кодом: `element/list`,
  `element/{id}`, `element/slug/...`;
- `cml2Link` — поле-привязка: фильтр `cml2Link.element.id`, выборка
  `cml2Link.element.id|name|code`; значение — колонка `product_id`;
- `catalogPrice`, `stocks`, `catalogQuantity` у предложений — как у простых товаров;
- `extra_element_api_codes` в правилах хлебных крошек.

Расширения (аналоги из компонентов каталога Битрикса):

- **`catalogType`** в `select` — 1/3/4/6 (`CATALOG_TYPE`); `null` вне каталога.
- **Цена «от».** У товара типа 3 `catalogPrice` той же формы, что у простого товара: цена
  самого дешёвого (по базовой цене) активного доступного предложения плюс `"fromOffers":
  true`; `stocks` — остатки, сложенные по складам среди активных предложений. Тип 6 —
  `catalogPrice: null`, `stocks` пустой. Аналог `MIN_PRICE` в `catalog.section`.
- **Фильтр `offers`** — ключ внутри `filter`, значение — фильтр bxapi по коллекции
  предложений:
  `{"filter": {"active": "Y", "offers": {"active": "Y", "volume.value": "4"}}}` →
  `EXISTS (SELECT 1 FROM collection_items o WHERE o.product_id = e.id AND …)` (аналог
  `CIBlockElement::SubQuery('PROPERTY_CML2_LINK', …)`). Работает внутри `logic: OR`, в
  `hasElements` разделов, учитывается в `MAX_DEPTH`. Коллекция без предложений — ошибка
  неизвестного поля, как для любого чужого ключа. Внутри `offers` ключ `offers` — тоже
  ошибка неизвестного поля.

Пакетно: цены «от», остатки и `catalogType` — запросами на страницу, не на запись.

## Корзина и заказ

- `productId` предложения кладётся как обычный товар. Товар типа 3 или 6 —
  `product_not_found` «Товар не найден» (как недоступный товар в `ensure_purchasable`).
- Позиция предложения: `name` — название предложения; `slug` — адрес товара-родителя, если
  у коллекции предложений пуст шаблон детальной страницы (аналог `#PRODUCT_URL#`);
  `image` — картинка предложения, иначе товара; `article` и `properties` по
  `item_properties` — из предложения, пустое значение — из товара.
- При добавлении в `props` пишутся: поля `in_basket` предложения и товара (`code`,
  `name` поля, отображаемое значение; множественные — через запятую), затем
  `PRODUCT.XML_ID` и `CATALOG.XML_ID` (как кладёт Битрикс). При увеличении количества
  существующей позиции `props` не меняются.
- Заказ: ЛК `items[].properties` — `props` позиции плюс `STORE_ID`, формат `{code, name,
  value}`; карточка заказа в админке и письмо — свойства под названием позиции, кроме
  служебных `*.XML_ID`. ЛК `items[].weight` — `weight` товара позиции (сейчас 0). Списание остатков — с предложения; доступность товара пересчитает
  триггер.

## Импорт из Битрикса

- `b_catalog_iblock (IBLOCK_ID, PRODUCT_IBLOCK_ID, SKU_PROPERTY_ID)` →
  `product_collection_id`, `sku_field_id`;
- значения `CML2_LINK` → `product_id` (поле `CML2_LINK` создаётся как у новой коллекции
  предложений, значение в JSONB не дублируется);
- `b_catalog_product.TYPE`, `WEIGHT` → `type`, `weight` (тип родителей затем сверит
  триггер);
- `b_iblock_property_feature` (`IN_BASKET`, `OFFER_TREE`, `IS_ENABLED = 'Y'`) → флаги
  полей.

Повторный импорт идемпотентен. В локальный Битрикс ничего не пишется.

## Наш API `/api/v1/iblocks`

Пути и ключи не меняются. У записи добавляются `product_id` (только у предложений) и
`catalog.type`. Коллекция предложений доступна как обычная.

## Проверка

- Модульные: сочетания генератора и лимит 100; шаблон названия; выбор цены «от»; сборка
  `props`; разбор фильтра `offers` (вложенный `offers`, глубина).
- `sqlx::test`: триггер (добавили предложение → 3; удалили последнее → 6; обнулили остаток
  единственного предложения → родитель недоступен; сменили `product_id` → пересчёт обоих
  родителей); каскадное удаление; товар типа 3 в корзину → `product_not_found`;
  предложение в корзину → `props`; заказ сохраняет `props`, ЛК отдаёт их; фильтр `offers`
  (простой, внутри OR, в `hasElements`); `cml2Link.element.id`; `catalogPrice` «от» и
  `stocks`; генератор (создание и пропуск дублей); импорт на подготовленных строках `b_*`.
- Сквозной сценарий на демо-данных в dev-базе: коллекции `demo_goods` и
  `demo_goods_offers`, товар «Масло ATF», предложения 1 л и 4 л из генератора; через
  bxapi — список с ценой «от», фильтр `offers`, предложение в корзину, оформление заказа,
  свойства в ЛК, письмо, карточка заказа в админке. Демо-данные и заказ остаются в базе.
- Регрессия: фронт трансопта — каталог, корзина, заказ, ЛК без изменений.
- Нагрузка: `ab` на `element/list` с фильтром `offers` и `catalogPrice` по синтетике
  1000 товаров × 4 предложения.
