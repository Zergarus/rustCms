# Складской учёт (ядро) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** склады как модуль `catalog` Битрикса — документы (приход, оприходование, перемещение,
возврат, списание), резервы по позициям заказа с пятью условиями и автоснятием, списание при
отгрузке со склада отгрузки, в режимах со складским учётом и без; админка, обмен с 1С, перенос.

**Architecture:** новый модуль `src/stock/`:
- `mod.rs` — настройки и пересчёт доступного количества;
- `documents.rs` — проведение и отмена документов: чистый план движений плюс применение под
  блокировкой;
- `reserve.rs` — резервы позиций заказа: одна точка `sync` на события заказа;
- `ship.rs` — списание при отгрузке;
- `cleaner.rs` — фоновое автоснятие.

Счётчики резерва товара и склада и доступное количество при изменении `basket_reservations`
поддерживает триггер БД. Поэтому каскадное удаление заказа или позиции само возвращает резерв.
Физический остаток склада (`amount`) меняют только документы, отгрузки, ручная правка без учёта
и обмен с 1С.

**Tech Stack:** Rust 2024, Axum 0.8, SQLx 0.9 (`#[sqlx::test]`), PostgreSQL 17, MiniJinja, HTMX.

**Spec:** `docs/superpowers/specs/2026-10-27-stores-design.md`

## Global Constraints

- Миграция `0023_stores.sql`; `0001`–`0022` применены — не менять.
- Склады и остатки: `catalog_stores`, `catalog_store_amounts (item_id, store_id, amount)`,
  `catalog_products (item_id, quantity, quantity_trace, can_buy_zero, …)`. Позиции заказа —
  `cart_items` с `order_id` и `store_id`. Учёт количества товара — `PurchaseInfo.quantity_trace`
  (значение по умолчанию — опция `catalog.default_quantity_trace`). Товары без учёта количества
  резерв и остатки не меняют.
- Блокировки: строки товаров и остатков — только через `catalog::load_locked` (порядок по id),
  до любого изменения остатков и резервов.
- Опции и умолчания (таблица `options`, `Y`/`N`):
  - `catalog.default_use_store_control` = `N`;
  - `catalog.enable_reservation` = `Y`;
  - `catalog.allow_negative_amount` = `N`;
  - `catalog.store_document_numbers_<A|S|M|R|D>` = `0`;
  - `sale.product_reserve_condition` = `O` (значения `O`, `R`, `P`, `D`, `S`);
  - `sale.product_reserve_clear_period` = `0`;
  - `sale.allow_deduction_on_delivery` = `N`.
- Отгрузка, по которой движутся остатки, — основная: `min(id)` среди отгрузок заказа (так уже
  работает `repo::set_shipment`). Позиции заказа отгружаются вместе с ней.
- Тексты Битрикса дословно (`#…#` подставляется):
  - «Указанное количество товара #PRODUCT# больше, чем есть на складе #STORE#»;
  - «Не указан поставщик.»;
  - «Не найдены позиции документа складского учета с идентификатором ##ID#»;
  - «Не найден элемент инфоблока с идентификатором ##ID#, присутствующий в документе складского
    учета»;
  - «Неверный тип товара ##ID# (#NAME#) в документе складского учета»;
  - «Некорректное количество товара ##ID# (#NAME#) в документе складского учета»;
  - «Склад-получатель не должен совпадать со складом-отправителем»;
  - склад строки: «Для товара #PRODUCTS# не указан / указан несуществующий / указан
    деактивированный склад <вид>», где `<вид>` — «прихода» (A), «оприходования» (S), «назначения»
    (M, получатель), «возврата» (R), «списания» (D); для отправителя перемещения —
    «склад-отправитель». `#PRODUCTS#` = «<id> <название>»;
  - отгрузка:
    - «Не указаны склады для отгрузки товара #PRODUCT_NAME# (##PRODUCT_ID#)»;
    - «Недостаточное количество товара "#PRODUCT_NAME#" (##PRODUCT_ID#) на складе "#STORE_NAME#"
      (##STORE_ID#) для отгрузки.»;
    - «Недостаточное количество товара #PRODUCT_NAME# (##PRODUCT_ID#) для отгрузки»;
  - отмена отгруженного заказа: «Некоторые товары уже отгружены».
- Названия документов: «Приходная накладная #N», «Оприходование #N», «Перемещение #N», «Возврат
  товара #N», «Списание #N».
- Регрессия: при выключенном складском учёте и без новых заказов ответы bxapi и `/api/v1` байт в

- Тексты интерфейса и комментарии — по-русски, как в окружающем коде.
- Сообщения коммитов — по-русски, без упоминаний ИИ/Claude и строк `Co-Authored-By`.
- В локальный Битрикс запросы с побочными эффектами не отправляются; `docs/benchmark-bitrix-vs-rust.md`

## Review Focus

1. **Включение складского учёта на работающем сайте**, где `quantity` правили руками. Ожидание:
   доступное сразу пересчитывается по инварианту, а не «прыгает» при первом движении. Тест в
   Task 1 `enabling_store_control_recalculates`.
2. **Склад деактивирован, а на нём остаток и резервы.** Ожидание: доступное товара пересчитано без
   этого склада, резервы на нём живут до снятия или отгрузки. Тест в Task 1
   `deactivating_store_recalculates`.
3. **Заказ удалён обменом с 1С вместе с резервами.** Ожидание: резерв товара и склада и доступное
   вернулись. Тест в Task 1 `deleting_reserved_order_releases` — проверяет триггер.
4. **Два документа или документ и оформление заказа на один товар одновременно.** Ожидание: второе
   ждёт блокировку и видит актуальный остаток, минус не появляется. Тест в Task 2
   `conduct_waits_for_lock`: две транзакции, вторая проведения после коммита первой получает
   ошибку минуса.
5. **Позиция с товаром без учёта количества** (`quantity_trace` = нет). Ожидание: резерв не
   ставится, отгрузка не трогает остатки. Тесты в Task 3 `untraced_line_not_reserved` и Task 4
   `untraced_line_not_deducted`.

`basket_reservations` получает ещё `item_id BIGINT NOT NULL` — товар позиции, без FK. Его
заполняет вставка: триггер при каскадном удалении позиции не должен зависеть от строки
`cart_items`.

**Триггер** `basket_reservations_counters`: `AFTER INSERT OR UPDATE OR DELETE`, функция считает
`delta = NEW.quantity − OLD.quantity` (вставка — `OLD` 0, удаление — `NEW` 0) по
`item_id` резерва. Триггер делает:
- `catalog_products.quantity_reserved += delta`, `quantity −= delta`;
- при `store_id` — `catalog_store_amounts.quantity_reserved += delta` (строка создаётся при
  отсутствии);
- при `UPDATE` со сменой `store_id` — вычесть со старого склада, прибавить на новый.

**Перевод существующих заказов.** Заказы неотменённые, `stock_deducted`, без отгруженной
основной отгрузки; позиции товаров с учётом количества (`COALESCE(quantity_trace, опция
default_quantity_trace = 'Y', TRUE)`):
1. `catalog_products.quantity += Σ` по позициям; `amount` склада позиции `+= quantity`;
2. `INSERT INTO basket_reservations` (`date_reserve_end` NULL) — триггер вернёт `quantity` и
   поставит резервы.
