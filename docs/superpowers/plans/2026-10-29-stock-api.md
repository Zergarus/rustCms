# Склады: API-ключи и API склада (5б-2) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** внешние системы работают со складом по API-ключам со scope: читают склады, остатки,
товары, документы и поставщиков, ведут черновики документов и проводят их по правилам 5а/5б-1.

**Architecture:** `src/apikeys.rs` — ключи (выпуск, отзыв, проверка) и extractor `ApiAccess`;
`src/stock_api/` — роутер `/api/stock/v1` с тонкими обработчиками поверх `src/stock` и свой тип
ошибок с JSON-ответом. Админка — блок «API-ключи» в карточке пользователя.

**Tech Stack:** Rust 2024, Axum 0.8, SQLx 0.9 (`#[sqlx::test]`), PostgreSQL 17, MiniJinja, HTMX;
`sha2`, `rand`, `hex` уже в зависимостях.

**Spec:** `docs/superpowers/specs/2026-10-29-stock-api-design.md`

## Global Constraints

- Миграция `0026_api_keys.sql`; `0001`–`0025` применены — не менять.
- Ветка `feature/stores-api` (от `main`).
- Ключ: `cms_<prefix>_<секрет>`; `prefix` — 8 символов `[a-z0-9]`, секрет — 32 символа
  `[A-Za-z0-9]` из криптографического генератора; хранится только `sha256(секрет)` hex. Полный
  ключ — только в ответе на выпуск; в логах, ответах, админке — `cms_<prefix>_…`.
- Scope: `stock.read`, `stock.write`, `stock.conduct`. Все методы требуют ещё право
  `shop.manage` пользователя ключа; `purchasing_price` в `lookup` — право `catalog.purchase_info`.
- Тексты (дословно):
  - 401 `{"error":"unauthorized","message":"Неверный или отозванный API-ключ"}` +
    `WWW-Authenticate: Bearer`;
  - 403 `{"error":"forbidden","message":"Нужен scope <scope>"}` /
    `{"error":"forbidden","message":"Нужно право <permission>"}`;
  - 409 `«Складской учёт выключен»`; `«Документ с внешним кодом <X> уже есть»` (+ `"id"`);
  - 422 `{"error":"rejected","messages":[...]}`; `«Не найден товар с внешним кодом <X>»`;
  - админка: «Сохраните ключ — потом его не показать».
- Списки: `limit` по умолчанию 50, максимум 500; ответ `{"items":[...],"total":N}`.
- `last_used_at`/`last_used_ip` — не чаще раза в минуту на ключ.
- Логика склада только через `src/stock` (`documents::create/update/delete/conduct/cancel`,
  `barcodes::find_item`); никакой второй реализации правил.
- Регрессия: ответы bxapi и `/api/v1` байт в байт как до подпроекта; эталоны `tests/fixtures/**`
  не меняются.
- Тексты интерфейса и комментарии — по-русски; коммиты по-русски, без упоминаний ИИ и
  `Co-Authored-By`; `docs/benchmark-bitrix-vs-rust.md` не коммитится; локальный Битрикс не
  трогаем.
- Проверка после задачи: `cargo test` (вывод в файл), `cargo clippy --all-targets -- -D warnings`,
  `cargo fmt --check`.

## Review Focus

1. **Ключ передан с пробелами или в нижнем регистре схемы** (`bearer cms_…`, лишние пробелы).
   Ожидание: принимается (схема без учёта регистра, trim). Тест в Task 2 `bearer_scheme_case_insensitive`.
2. **Пользователя ключа сделали суперадминистратором или убрали из группы с `shop.manage`.**
   Ожидание: права пересчитываются на каждом запросе. Тест в Task 2 `right_revoked_takes_effect`.
3. **`PUT` черновика, который другой клиент только что провёл.** Ожидание: 409, документ не
   изменён (проверка статуса под блокировкой строки, как в `documents::update`). Тест в Task 4
   `put_conducted_conflict`.
4. **Строка с `item_xml_id`, которого нет, плюс ошибка в другой строке.** Ожидание: 422, ничего не
   создано. Тест в Task 4 `unknown_item_xml_id_rejected`.
5. **`limit=100000` или `offset=-1`.** Ожидание: 400 или ограничение до 500, не падение. Тест в
   Task 3 `list_params_bounds`.

    expires_at: Option<DateTime<Utc>> }`
  - `pub async fn issue(db: &PgPool, key: &NewKey, by: i64) -> AppResult<(i64, String)>` — id и
    полный ключ; пустое имя / пустые или неизвестные scope → `AppError::BadRequest`.

- Produces (`stock.write` + `shop.manage`):
  - `DocInput` получает `pub xml_id: String` (пусто — нет кода); нарушение уникальности в
    `create`/`update` даёт `StockError::Rejected` с текстом «Документ с внешним кодом X уже есть»

  - `POST /documents` → 201; тело по спеке; `item_id` или `item_xml_id` ровно одно (оба / ни

    списком, до создания). `responsible_id` и автор — `access.user.id`.
  - `PUT /documents/{id}` — проведённый → 409 с текстом `documents::update` (в транзакции, статус
    проверяется под блокировкой); `DELETE` → 204, проведённый → 409.
  - Складской учёт выключен (`stock::settings`) → 409 «Складской учёт выключен» для всех методов
    документов (и чтения документов — тоже, как раздел в админке).
