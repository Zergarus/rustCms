# Корзина и торговый каталог — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** корзина по контракту bxapi (гостевая и пользовательская, объединение при входе, лимиты остатков) и раздел админки «Магазин» с включением торгового каталога у любого инфоблока.

**Architecture:** новый слой ядра `src/catalog/` (цены, остатки, правила покупки) и `src/cart/` (покупатели, позиции, расчёт снимка — чистая функция, объединение корзин). HTTP по контракту bxapi — `src/bxapi/cart.rs`; админка — `src/admin/shop/`. Настройки сайта (аналог `bxapi.basket`) — поле `cart` в `bxapi::project::Project`.

**Tech Stack:** Rust 2024, Axum 0.8, SQLx 0.9 (PostgreSQL), MiniJinja + HTMX, sha2.

**Spec:** `docs/superpowers/specs/2026-10-07-cart-design.md`

## Global Constraints

- Всё в `src/` — ядро CMS без кода конкретного сайта; настройки трансопта — только в `projects/transopt.rs` (не в git).
- Новая миграция — `migrations/0009_cart.sql`; существующие миграции не меняются.
- Новых зависимостей нет. `snapshot` — sha256 (крейт `sha2`), усечённый до 40 hex-символов: фронт значение не разбирает, только сравнивает.
- Cookie гостя — `CMS_BUYER` (HttpOnly, SameSite=Lax, Secure по `COOKIE_SECURE`, 365 дней, path `/`); в БД — только sha256 токена.
- Коды ошибок: `product_not_found` (404), `cart_item_not_found` (404), `cart_change_failed` (400), `invalid_quantity` (400); тексты: «Доступно N шт.», «Склад N недоступен».
- Право админки — `shop.manage` (константа `SHOP_MANAGE` в `src/access.rs`).
- Ответы bxapi — через `bxapi::success` / `BxError` (обёртка `{status, data, errors}`).
- Комментарии и тексты интерфейса — на русском, как в остальном коде.
- В локальный Битрикс не отправлять запросы с побочными эффектами.
- Коммиты — без упоминаний ИИ; запуск тестов — `rtk proxy cargo test <имя>` (обёртка rtk прячет вывод обычного `cargo test`).

## Review Focus

1. Количество строкой, дробью, нулём или отрицательным в `POST /cart/items` — ожидается `invalid_quantity`, корзина не меняется (тест в Task 5).
2. Товар неактивный или из инфоблока без флага «Торговый каталог» — `product_not_found` при добавлении, `isAvailable: false` у уже лежащей позиции (тесты в Tasks 3 и 5).
3. Склад деактивирован после выбора — `store: null`, при `required_props = ["store"]` — `canCheckout: false` (тест в Task 3).
4. Неизвестный или подделанный токен в `CMS_BUYER` — пустая корзина без ошибки, новый покупатель создаётся только при добавлении товара (тест в Task 5).
5. При объединении корзин сумма количеств превышает остаток — количества всё равно складываются, позиция остаётся с итоговым количеством (лимит проверит оформление заказа) (тест в Task 4).
