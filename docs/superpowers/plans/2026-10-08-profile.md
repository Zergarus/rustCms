# Личный кабинет Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET/POST /profile`, `GET /profile/orders[/{id}]` по разделу 7 контракта bxapi, файлы
и отгрузка в карточке заказа в админке.

**Architecture:** Загрузка заказов пользователя пачкой — `src/sale/history.rs` (БД, тесты
`sqlx::test`). Сборка JSON заказа — чистые функции в `src/bxapi/profile_orders.rs`, им на
вход отдаются заранее собранные справочники (склады, товары, файлы). Профиль — чистый
разбор ввода в `src/bxapi/profile.rs` + запись в `src/users.rs`. Админка — отдельные
формы «Файлы» и «Отгрузка» в карточке заказа.

**Tech Stack:** Rust 2024, Axum 0.8 (`Multipart`), SQLx 0.9, PostgreSQL 17, MiniJinja.

**Spec:** `docs/superpowers/specs/2026-10-08-profile-design.md`

## Global Constraints

- В репозиторий — только универсальный код с аналогом в ядре/модуле Битрикса;
  проектное — в `projects/transopt.rs` (не в git). Фронт не меняется.
- Ответы — конверт `success(...)` / `BxError`; без сессии — HTTP 401, `code: "unauthorized"`,
  сообщение «Требуется авторизация».
- Ключи JSON — camelCase; суммы — числа; даты — ISO 8601 (`%Y-%m-%dT%H:%M:%S%:z`, локальный
  пояс сервера, `chrono::Local`).
- `ProfileConfig` по умолчанию: `fields = editable_fields = [NAME, LAST_NAME, SECOND_NAME,
  EMAIL, PERSONAL_PHONE, PERSONAL_PHOTO]`, `include_orders_count = true`,
  `orders_limit = 50`, предел 200, `order_created_at_format = "d.m.Y H:i:s"`.
- CSRF в Rust-API не проверяется ни одним эндпоинтом — POST `/profile` так же (как
  «остальные изменяющие эндпоинты»).
- Тесты: `rtk proxy cargo test`; после возврата `projects/` — `touch projects`. Clippy чистый.
- Коммиты — по-русски, без упоминаний Claude/ИИ.
- В каталоге нет веса товара и `xml_id` склада: `weight` всегда 0, `store.xmlId` —
  `extra.xml_id` склада строкой, иначе `""`.

## Review Focus

1. Чужой заказ: `/profile/orders/{id}` чужого пользователя и заказ гостя (`user_id IS NULL`) —
   404, а не данные. Тест — Task 3 `detail_of_other_user_is_none`.
2. Сохранение текстовых свойств в админке не должно стирать файлы (сейчас
   `update_properties` удаляет все значения). Тест — Task 6 `update_properties_keeps_files`.
3. `POST /profile` с полем, которого нет в `editable` (`login`, `isAdmin`, `active`), — молча
   игнорируется. Тест — Task 5 `pick_updates_only_editable`.
4. Файл заказа, удалённый из `files`, и мусор в значении (`"abc,,12"`) — пропускаются, ответ
   не падает. Тест — Task 2 `file_value_skips_missing_and_garbage`.
5. `limit=0`, `limit=1000`, `limit=abc`, `offset=-5` — по умолчанию/предел/0, не 500. Тест —
   Task 2 `page_parsing`.
