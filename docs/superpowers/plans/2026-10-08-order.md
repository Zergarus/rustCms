# Оформление заказа — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** оформление заказа по контракту bxapi (`order/form`, `order/summary`, `order/submit`, целиком и частями) со списанием остатков, гостевыми учётными записями и письмами; заказы и настройки оформления в админке; перенос настроек из Битрикса.

**Architecture:** новый слой ядра `src/sale/` (аналог модуля `sale`): справочники, чистые функции формы, проверки, выбора состава, плана остатков, полей писем; SQL заказа — `src/sale/repo.rs`. HTTP по контракту — `src/bxapi/order.rs`, админка — `src/admin/shop/` (заказы и настройки). Настройки сайта (аналог `bxapi.order.*`) — поле `order` в `bxapi::project::Project`.

**Tech Stack:** Rust 2024, Axum 0.8, SQLx 0.9 (PostgreSQL), MiniJinja + HTMX, lettre (через `mail::send_event`).

**Spec:** `docs/superpowers/specs/2026-10-08-order-design.md`

## Global Constraints

- Всё в `src/` — ядро CMS без кода конкретного сайта; настройки трансопта — только в `projects/transopt.rs` (не в git).
- Новая миграция — `migrations/0010_order.sql`; существующие миграции не меняются. Новых зависимостей нет.
- Коды ошибок submit (HTTP 400, кроме отмеченных): `missing_snapshot`, `invalid_person_type`, `invalid_delivery`, `invalid_payment`, `payment_forbidden` (403), `invalid_property`, `empty_basket`, `basket_changed` (409), `user_provision_failed` (500), `order_write_exception` (500). Текст `basket_changed`: «Состав или стоимость корзины изменились. Обновите корзину перед оформлением.»; при нехватке остатка — «Доступно N шт.» (как в корзине).
- `basket_changed` всегда несёт `customData: {"basket": <актуальный снимок корзины>}`; `invalid_property` — `customData: {"field": "<код свойства>"}`.
- Права: заказы — `orders.manage` («Работа с заказами», константа `ORDERS_MANAGE`), настройки оформления — `shop.manage`. Суперадмину доступно всё.
- Почтовые события: `SALE_NEW_ORDER`, `SALE_STATUS_CHANGED_<код>` (если у статуса `notify`), `SALE_ORDER_CANCEL`, `SALE_ORDER_PAID`; ошибка отправки — `tracing::warn!`, операция с заказом не откатывается.
- Ответы bxapi — через `bxapi::success` / `BxError`. Значения, введённые покупателем, в админке выводятся только с автоэкранированием (без `|safe`).
- Комментарии и тексты интерфейса — на русском, как в остальном коде.
- В локальный Битрикс не отправлять запросы с побочными эффектами (чтение MySQL при импорте — можно).
- Коммиты — без упоминаний ИИ; тесты — `rtk proxy cargo test <имя>`; после возврата `projects/` на место — `touch projects`.

## Review Focus

1. Двойное нажатие «Оформить» / повторный `submit` с теми же `basketItems` — второй запрос получает `basket_changed` (позиции уже в заказе), дубля заказа нет (тест в Task 4 `pick_items_rejects_missing_item`, гонка — Task 11).
2. Гость вводит email существующего пользователя в другом регистре или с пробелами — заказ привязывается к нему, новый пользователь не создаётся (тест в Task 6 `guest_contacts_normalizes`).
3. Обязательное свойство из пробелов или обязательный флажок со значением `N` («Подтверждаю введённые данные») — `invalid_property` (тест в Task 4 `required_blank_and_unchecked`).
4. Непубличная («Без доставки») или неактивная доставка, переданная по id, — `invalid_delivery` (тест в Task 3 `find_delivery_skips_hidden`).
5. Правка состава отменённого заказа или товара без учёта количества — остатки не меняются (тесты в Task 5 `plan_ignores_untraced` и Task 10 `edit_canceled_keeps_stock`).
