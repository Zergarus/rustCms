## P1 — важно для продукта

### 1. ~~Тип поля «редактор блоков» (аналог `sprint.editor`)~~ — сделано

Сейчас поля коллекции — это `string`, `text`, `number`, `boolean`, `date`,
`list`, `element`, `file`. Модуль `sprint.editor` в Битриксе — визуальный
блочный редактор контента (user type свойства): контент хранится как массив
JSON-блоков, а не как один HTML-текст. Без него нашим редакторам приходится
вставлять HTML в `text`, и вёрстка страниц разъезжается.

Нужен **тип поля `blocks`** в коллекции:

- Хранение: JSON-массив блоков `[{ "type": "text", "data": { … } }, …]` в
  `field_values`; снимки версий и экспорт работают без изменений.
- Набор блоков: заголовок, текст (абзацы/списки/ссылки), изображение,
  галерея, видео/встраивание, цитата, таблица, разделитель, файл, HTML/код,
  кнопка.
- Редактирование в админке: добавить блок, переставить (drag&drop), дублировать,
  удалить, настройки блока (выравнивание, размер, подпись, ссылка).
- Медиа: загрузка прямо в блок, переиспользование `files` (ресайзы, `upload/`).
- Отдача: в bxapi — и JSON блоков, и готовый HTML, собранный шаблонами блоков
  на сервере; HTML-блок проходит очистку (allowlist), иначе это XSS.
- Права: редактор доступен тем, у кого есть запись в коллекцию; шаблоны блоков
  могут переопределяться проектом.
- Паритет с `sprint.editor`: JSON-формат намеренно не копируем, но при импорте
  из Битрикса конвертируем его блоки в наши (отдельная задача импорта).

Оценка: крупный (новый kind поля, UI-редактор, рендер, санитайзер, миграция
данных). Без него контентные проекты остаются на HTML-тексте.
