# Скорость бэкенда: Битрикс против Rust CMS

Дата замера: 2026-10-09. Проект: фронт TransOpt (Nuxt) через контракт `mediagroup.bxapi`.
Rust CMS — ветка `feature/bitrix-compat`, коммит `e2a4607`, release-сборка.

## Итог

На одинаковых запросах фронта Rust CMS под нагрузкой обрабатывает **в 8–89 раз больше
запросов в секунду**, а одиночный запрос отвечает **в 9–60 раз быстрее**. Ответы по
содержимому совпадают с Битриксом (сверено ранее на эталонных ответах). Ошибок нет ни в
одном прогоне.

## Под нагрузкой (16 параллельных соединений)

| Запрос фронта | Rust CMS, rps | Битрикс, rps | Rust, p50 / p99 | Битрикс, p50 / p99 | Rust быстрее |
|---|---:|---:|---:|---:|---:|
| Карточка товара | 2 237 | 36 | 7 / 11 мс | 403 / 654 мс | **×62** |
| Товары раздела по маркировке | 1 243 | 46 | 12 / 30 мс | 309 / 408 мс | **×27** |
| Разделы каталога с `hasElements` | 406 | 51 | 35 / 164 мс | 282 / 373 мс | **×8** |
| Коробки модели авто (ответ 72 КБ) | 935 | 32 | 18 / 24 мс | 444 / 677 мс | **×29** |
| Поиск «U660» | 1 269 | 43 | 15 / 18 мс | 328 / 516 мс | **×29** |
| Список схем | 5 332 | 60 | 3 / 5 мс | 251 / 331 мс | **×89** |

rps — запросов в секунду; p50 / p99 — время ответа, быстрее которого отвечают 50% и 99%
запросов.

## Как мерили

- Инструмент: `ab` (ApacheBench) с keep-alive. Под нагрузкой: Rust — 2 000 запросов,
  Битрикс — 200 запросов, по 16 соединений. Один запрос: 300 и 30 запросов подряд.
  Перед каждым замером — прогрев.
- Запросы: те же POST-запросы `/api/v1/iblock/...` с теми же телами, что шлёт фронт.
- Машина: Apple M4 Pro, 14 ядер, macOS. Оба бэкенда на одной машине, замеры по очереди.
- Rust CMS: нативный процесс, PostgreSQL 17 в Docker.
- Битрикс: локальный стенд в Docker (traefik → nginx → php-fpm 8.3 с OPcache, MariaDB 10.11).

## Оговорки

Цифры Битрикса получены на локальном dev-стенде, поэтому сравнение ориентировочное, хотя
разница исчисляется десятками раз:

- в php-fpm загружен Xdebug (из-за него отключён JIT), `pm.max_children = 5` — на
  продовом сервере Битрикс будет быстрее, но не на порядок;
- Битрикс отвечает через HTTPS и дополнительный прокси traefik, Rust — напрямую по HTTP;
- Docker на macOS добавляет накладные расходы виртуализации (PostgreSQL для Rust тоже в
  Docker);
- кеш компонентов Битрикса на эти API-запросы не действует, у Rust кеша ответов тоже нет —
  обе стороны каждый раз ходят в БД.

Эндпоинты корзины, заказа и личного кабинета на Битриксе не замерялись: эти запросы
создают сессии и записи в базе локального Битрикса. Для справки, Rust на них: профиль —
3 496 rps (p99 8 мс), список заказов в ЛК — 651 rps (p99 35 мс).

Самое медленное место у Rust — разделы с `hasElements` (×8): там при необходимости можно
добавить индексы.
