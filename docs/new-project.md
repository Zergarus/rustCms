# Новый проект на CMS

Чек-лист от пустой установки до рабочего сайта. Всё, что специфично для
конкретного сайта, живёт в модуле проекта (`project/mod.rs`, в репозиторий CMS
не попадает) и в настройках админки.

## 1. Установка и доступ

- [ ] Поднять CMS по [installation.md](installation.md), задать `DATABASE_URL`,
      `CORS_ORIGINS`, `COOKIE_SECURE`.
- [ ] Создать администратора: `cargo run -- create-admin admin`.
- [ ] «Настройки сайта»: название, домен, отправитель, SMTP.

## 2. Контент

- [ ] Коллекции и поля: типы контента, разделы, права групп.
- [ ] Записи, разделы, SEO-метаданные (Title/Description/H1, canonical, robots).
- [ ] Почтовые шаблоны («Письма»): события под формы и заказы.
- [ ] Sitemap («SEO → Sitemap»): типы, коллекции, шаблоны адресов.

## 3. Модуль проекта

Положить `project/mod.rs` с функцией `pub fn project() -> Project` — сборка
подхватит его автоматически (`build.rs`). Минимум:

```rust
use crate::bxapi::project::Project;

pub fn project() -> Project {
    Project {
        image_widths: vec![160, 480, 960],
        ..Project::default()
    }
}
```

Дальше по необходимости (примеры — в `project/README.md`):

- [ ] формы: `forms`/`form_extensions`, либо `config/forms.toml`;
- [ ] декораторы ответов, группы поиска, алиасы, правила крошек и редиректов;
- [ ] платёжные провайдеры: `payment_extensions`;
- [ ] условия скидок: `discount_condition_hook`;
- [ ] проверки форм (капча) — `form_guards`;
- [ ] хуки обмена с 1С.

## 4. Витрина

- [ ] `CORS_ORIGINS` — домен фронтенда, API-ключи (если нужны) в админке.
- [ ] Проверить bxapi-контракт: каталог, корзина, заказ, профиль, формы.
- [ ] Проверить `robots.txt`/sitemap на домене.

## 5. Обмен данными

- [ ] Импорт из Битрикса: `cargo run -- import-bitrix` (подробности — README,
      раздел «Перенос из Битрикса»).
- [ ] Обмен с 1С: настройки на странице «Обмен с 1С», проверить каталог и
      заказы на тестовой базе.

## 6. Перед запуском

- [ ] HTTPS и `COOKIE_SECURE=true`.
- [ ] SMTP проверен: регистрация, сброс пароля, письмо о заказе.
- [ ] Бэкапы базы и `UPLOAD_DIR` настроены.
- [ ] Права групп выданы по минимуму (админка → «Группы и права»).
- [ ] Прогнаны сценарии: регистрация → подтверждение → вход, заказ → оплата →
      статус, форма с вложением, sitemap.

## Чего в ядре нет

Список известных пробелов — [bitrix-parity.md](bitrix-parity.md) и
[tech-debt.md](tech-debt.md). Отзывы, скидка пользователя из 1С и документы
(счёт/чек) — проектные расширения, не ядро.
